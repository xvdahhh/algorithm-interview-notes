01.01

复杂度：统计操作，而不是数循环层数

知识与适用场景

分析时间时先确定输入规模；图常有 V、E 两个维度，矩阵有行数与列数。顺序代码的成本相加，嵌套代码要统计真实执行次数。两个嵌套循环并不必然是 O(n²)：如果内层指针全程只前进 n 次，总成本仍是 O(n)。

1.1 输入规模与大 O：描述增长，而非秒数

时间复杂度研究输入规模增大时，基本操作总量的增长速度。对数组可取 n=元素个数；对两个字符串应保留 n、m；对图通常保留 V、E。若两个输入规模独立，O(n+m) 不能直接写成 O(n)。

大 O 是渐近上界：存在常数 C 和 n₀，使足够大的 n 上 T(n)≤C·f(n)。Θ 是同阶紧确界，Ω 是下界。一个线性算法数学上也属于 O(n²)，但面试报告复杂度通常应给尽可能紧的量级，例如 Θ(n)，或按习惯写 O(n)。

3n²+8n+10 的最高阶项决定渐近增长，因此为 Θ(n²)。省略常数并不代表常数不重要：连续数组访问和频繁内存分配即使同阶，实际耗时也可能差很多。算法复杂度与实际运行时间需要分开回答。

1.3 循环次数怎么推：四类常见陷阱

代码形态实际次数结论
先扫描 n 次，再扫描 m 次n+m相加，而不是相乘
外层 n 次，内层每次都做 n 次n×nΘ(n²)
外层 i=0..n-1，内层 j=0..i1+2+…+n=n(n+1)/2Θ(n²)，内层随 i 变化也不能忽略

外层 n 次，每次内层重新从 1 倍增n×log₂nΘ(n log n)
内层指针全程只前进，不在外层重置总前进次数 ≤n外层+内层合计 Θ(n)

真正的“两个循环仍然线性”

right 总共前进 n 次；left 从 0 出发、从不后退、最多前进 n 次。因此所有 while 循环合在一起至多执行 n 次，总时间 O(n)。不能对每次外层都假设内层还能重新执行 n 次，因为 left 的进度被保留了。示例按字节处理字符串，长度需能用 int 表示。

下载 .cpp
int longestUniqueByWindow(const string& s) {
    array<int, 256> count{}; // 全部初始化为 0
    int left = 0, best = 0;
    for (int right = 0; right < (int)s.size(); ++right) {
        unsigned char c = static_cast<unsigned char>(s[right]);
        ++count[c];
        while (count[c] > 1) {
            unsigned char old = static_cast<unsigned char>(s[left]);
            --count[old];
            ++left;
        }
        best = max(best, right - left + 1);
    }
    return best;
}

1.4 最坏、平均、均摊：分别在对什么求结论

最坏复杂度：固定输入规模后，取最难输入。例如顺序查找的目标不在数组里，要扫描 n 次。最好情况可能第一次就命中，但通常不能只报最好情况。

平均复杂度：需要说明输入分布或随机化假设。例如哈希表在合理散列假设下查找平均 O(1)，严重冲突时单次可退化到 O(n)。如果算法自己随机选择基准，应说“对内部随机性的期望时间”，而不是把任意输入天然视为随机。

均摊复杂度：把一串操作的总成本分摊给每次操作，不要求输入随机。vector 追加通常是均摊 O(1)，某次扩容会搬移已有元素，单次最坏 O(n)。以容量翻倍为示意，扩容搬移总量 1+2+4+…<2n，连同 n 次插入仍为 O(n)。C++ 标准不要求具体按两倍扩容，但保证尾部追加的均摊复杂度。

1.5 空间复杂度：数峰值，不累计历史分配次数

空间复杂度通常指算法额外占用的最大同时存活空间。一个长度 n 的辅助数组是 O(n)；两个长度 n 的数组仍是 O(n)；n×m 的矩阵是 O(nm)。同一块临时空间重复复用，不把每轮占用简单相加。

需要声明是否计入输出。例如返回所有子集，输出本身最坏需要 Θ(n·2ⁿ) 个元素，辅助路径可只有 O(n)。不要把“辅助空间 O(n)”说成整个程序内存只有 O(n)。

函数按值接收 vector<int> 会复制输入，成本可能是 O(n) 时间与 O(n) 空间；const 引用不会复制整段元素。递归栈同样属于额外空间，下一节会按活跃栈帧计算。

推导 / 不变量

维护窗口中每个字符的最后位置。left 只前进，不回退；每个 right 只访问一次。循环不变量是 [left,right] 中没有重复字符，且 left 是当前可用的最靠左边界。

手推一个例子

对 "abba"：依次得到窗口 a、ab、b、ba。读到最后的 a 时，不能把 left 从 2 退回 1，否则窗口又包含重复的 b。

C++17
下载 .cpp
int longestUnique(const string& s) {
    array<int, 256> last;
    last.fill(-1);
    int left = 0, ans = 0;
    for (int right = 0; right < (int)s.size(); ++right) {
        unsigned char c = s[right];
        left = max(left, last[c] + 1);
        last[c] = right;
        ans = max(ans, right - left + 1);
    }
    return ans;
}
复杂度
时间 O(n)，额外空间 O(Σ)，这里 Σ=256。示例按字节处理字符串，中文 Unicode 字符需先解码。
易错点与边界
不要把平均、最坏、均摊复杂度混为一谈。哈希平均 O(1) 依赖散列表现；单调栈总 O(n) 来自每个元素最多入栈、出栈一次。

1.6 原模板逐步执行：为什么 “abba” 最后不能左移？

窄屏下可左右滑动表格，查看完整内容。

right / 字符旧 last[c]更新后的 left合法窗口 / best
0 / a-1max(0,0)=0a / 1
1 / b-1max(0,0)=0ab / 2
2 / b1max(0,2)=2b / 2
3 / a0max(2,1)=2ba / 2

把代码中的三个状态说清楚

last[c] 保存字符 c 最近一次出现的全局下标；left 是当前合法窗口的起点；best 保存所有已经扫描位置对应的最好答案。这三种信息不能混用。

当重复字符的旧位置位于窗口内，left 才需要越过它；若旧位置已经在窗口外，就保持 left 不变。max 恰好统一了这两种情况。更新 last[c] 必须在计算新 left 之后，否则会把当前字符误当成旧重复位置。

经典考点与练习

练习：LeetCode 3 无重复字符的最长子串；用两个循环版本重新证明总成本。

面试追问：关键点完整解答

为什么 left 必须取 max？

因为 last[c]+1 可能落在现有窗口左边。abba 的最后一个 a 旧位置为 0，此时 left=2；直接赋值为 1 会把已排除的 b 放回窗口，得到错误的 bba。max 保证窗口左边界单调且窗口仍合法。

如果字符集很大，甚至不能提前枚举，怎么改？

用 unordered_map<字符类型,int> 保存实际遇到的字符位置，不为所有可能字符预分配数组。若键是解码后的 Unicode 码点，可使用 char32_t；如果题目要求用户可见字符，还要考虑组合字符的分段规则。平均时间 O(n)，额外空间 O(min(n,Σ))。

为什么 unsigned char 不能省？

某些实现中的 char 是有符号类型，字节大于 127 时可能转成负下标。先转 unsigned char，使 byte 位于 0..255，才能安全索引长度 256 的数组。

O(Σ) 与 O(1) 到底哪个对？

若 Σ 固定为 256、唯一变量是 n，额外空间可写 O(1)；若同时分析可变字符集大小，则写 O(Σ)。两者是参数约定不同，并不矛盾。

看到两层循环应该怎样回答复杂度？

先说明每层变量是否重置，再统计总执行次数。独立重置的 n×n 为 O(n²)；全程单调推进的两个指针为 O(n)。答案要包含理由，不能按缩进层数直接下结论。

01.02

递归复杂度与栈空间

知识与适用场景

递归要分开分析总调用量与最大同时存活调用数。斐波那契朴素递归的调用树指数增长，但栈深只有 O(n)。归并排序每层处理 O(n) 个元素，层数 O(log n)，总时间 O(n log n)。

2.1 递归的三个问题：含义、基例、规模缩小

写递归前先定义函数到底返回什么，再列出不需要递归的最小输入，最后确认每次调用都更接近基例。以 sum(n) 表示 1..n 的和，sum(0)=0，sum(n)=n+sum(n-1)，状态规模每次减 1。

一次函数调用会暂停并等待子调用返回。只要局部状态在等待期间必须保留，就需要相应栈帧。C++ 不保证尾调用优化，所以不能仅凭“递归在最后一行”就声称栈空间 O(1)。

2.2 常见递推式：先数每层，再相加

T(n)=T(n-1)+T(n-2)+Θ(1)重复子问题产生指数数量节点Θ(φⁿ)，φ≈1.618；也常给 O(2ⁿ) 上界 / Θ(n)

归并排序为什么是 n log n，而不是 log n？

递归高度只是 log n，但每层要完成全部子区间的合并。第 0 层处理 n 个元素；第 1 层两个区间各处理 n/2，总计 n；第 2 层四个区间各处理 n/4，总计还是 n。每层 n 乘上约 log n 层，得到 O(n log n)。

这里默认合并一次长度为 k 的区间需 O(k)，且切分用下标或可控成本实现。如果额外复制子数组，应把复制成本算进每层；不要遗漏语言操作本身的成本。

2.3 总调用数和栈深为什么不能画等号？

深度优先执行递归时，当前只保留根到正在执行节点的一条调用链。左子树返回后，其栈帧已经释放，随后才进入右子树。因此一棵有 n 个节点的平衡二叉树，遍历时间 O(n)，调用栈却只有 O(log n)。

退化成链时同时存活的栈帧可有 n 个，所以同一 DFS 模板最坏栈空间为 O(n)。如果每层还分配长度与子问题规模相关的数组，应把该路径上同时存活的数组大小相加，而不只是数层数。

递归与滚动状态：同一个求和问题的两种空间成本

两者都执行 Θ(n) 次累加。递归版本最坏需要 Θ(n) 个栈帧，迭代版只保存 total 和 i，额外空间 O(1)。本例的 n 上界是数值范围说明，不代表递归到该深度可以安全运行；调用栈上限由环境决定。

C++17

long long sumRecursive(int n) {
    // 前提：0 <= n <= 1000000；实际递归深度仍可能超过系统栈限制。
    if (n == 0) return 0;
    return n + sumRecursive(n - 1);
}
long long sumIterative(int n) {
    long long total = 0;
    for (int i = 1; i <= n; ++i) total += i;
    return total;
}

2.4 记忆化如何消除重复调用？

朴素 fib(5) 会从多个分支重复计算 fib(3)、fib(2)。把每个 fib(k) 的结果缓存后，k=0..n 各算一次，时间降为 O(n)。但首次求解时仍可能深入 n 层，缓存数组与递归栈都是 O(n)。

递推版本按 k 递增填表可消除调用栈；若只依赖前两项，还可用两个变量压缩到 O(1) 辅助空间。空间优化是否可行，取决于是否还要恢复路径、保存全部答案等需求。

推导 / 不变量

平衡分治的层数来自每次规模减半；退化快排每次只减少一个元素，深度可达 n。下面用迭代快速幂展示另一种规模减半：每轮丢弃指数最低二进制位。

手推一个例子

计算 3^13：13 的二进制是 1101。依次考察 1、0、1、1，选取 3、81、6561 相乘；模运算保持结果大小受控。

C++17
下载 .cpp
long long modPow(long long a, long long e, long long mod) {
    // 前提：e >= 0，1 <= mod <= 1e9，保证乘法不溢出。
    long long ans = 1 % mod;
    a = (a % mod + mod) % mod;
    while (e > 0) {
        if (e & 1LL) ans = ans * a % mod;
        a = a * a % mod;
        e >>= 1;
    }
    return ans;
}
复杂度
时间 O(log(e+1))，额外空间 O(1)。递归版本需要 O(log(e+1)) 栈空间。
易错点与边界
深递归可能先触发栈溢出，再遇到时间限制。输出所有方案时，复制答案的成本也必须计入。

2.5 快速幂的推导与不变量

令原始底数为 A、原指数为 E。循环中保持 ans×aᵉ ≡ Aᴱ（mod mod）。如果 e 为偶数，用 (a²)^(e/2) 代替 aᵉ；如果 e 为奇数，先把一个 a 乘入 ans，再处理剩余偶数次方。

每轮 e 右移一位，a 自乘，必要时更新 ans。不变量成立且 e 最终为 0 时，ans×a⁰=ans 就是目标。模运算能在每一步执行，因为整数加法和乘法与取模兼容。

为什么原模板限制 mod ≤10⁹？

每次取模后 a 和 ans 都在 [0,mod) 内，所以相乘小于 10¹⁸，可以放入常见 64 位 long long。若 mod 接近 2⁶³，两个余数的乘积仍可能溢出，不能以“最后会取模”为理由忽略中间计算；需要适用编译器的更宽整数或专门的模乘方法。

快速幂每轮是常数次固定宽度乘法，故时间 O(log E)、空间 O(1)；E=0 单独是 O(1)。若换成任意精度整数，乘法本身不是 O(1)，需要重新计算位复杂度。

面试追问：关键点完整解答

指数为 0 时，为什么答案是 1%mod？

乘法的空积为 1，循环不进入，返回 1 取模后的结果。如果 mod=1，所有整数取模都为 0，所以返回 0。算法通常约定指数为 0 返回乘法单位元，这也给 0⁰ 选择了程序中的约定；若题目另有定义，按题目处理。

指数可以为负吗？

原函数前提是 e≥0，不支持负指数。实数幂可以先取倒数再处理正指数；模意义下的负幂需要底数存在乘法逆元，即与模数互质，不能直接做整数除法。

为什么归并排序不能只看递归深度？

深度仅表示有多少层，不表示每层只花常数时间。每层合并所有区间的工作总量为 O(n)，所以总时间是 O(n log n)。同时明确额外辅助数组 O(n)，栈 O(log n)。

如何安全处理 int 指数 INT_MIN 的取反？

先转换为 long long：long long e=n; 然后再执行 e=-e。直接 -n 会先在 int 中计算，INT_MIN 的正值超出 int 范围，事后再强转不能修复。

返回了 n 个结果，空间可以说 O(1) 吗？

只能明确说“除输出外的辅助空间 O(1)”。如果把返回容器计入整体额外内存，至少是 O(n)。输出指数多个方案时，时间也至少包含写出这些结果的成本。

01.03

正确性：让不变量贯穿代码

知识与适用场景

不变量是每轮循环前后始终成立的陈述。证明通常包含初始化、保持、终止三步。二分尤其依赖区间约定；先定义目标是第一个不小于 x 的位置，再选择边界更新。

3.1 先定义规格，再讨论代码正确

一个函数的规格至少包含：输入前提、输出含义和特殊情况。lowerBound 的输入必须非降序；输出是第一个值≥x 的下标，若不存在则返回 n。它与“寻找任意一个等于 x 的位置”不是同一问题。

正确性有两个部分：如果算法终止，结果符合规格；算法确实会终止。只有不变量而没有进度保证，可能无限循环；只有循环结束而没有不变量，可能快速得到错误答案。

3.2 不变量的三步证明

初始化：left=0、right=n 时，左侧 [0,left) 和右侧 [right,n) 都是空区间，因此“左侧全<x、右侧全≥x”自然成立，所有元素暂时未知。

保持：如果 a[mid]≥x，排序保证从 mid 往右的值都≥x，把 right 改为 mid 后右侧性质成立。如果 a[mid]<x，排序保证从左到 mid 都<x，把 left 改为 mid+1 后左侧性质成立。两种更新都不会丢失目标边界。

终止：循环停止时 left=right，已无未知元素。它之前全<x，从它开始全≥x，所以 left 正是第一个≥x 的位置。若 left=n，则整个数组都<x，返回 n 与规格一致。

3.3 两类区间约定不要混着写

闭区间 [l,r]，常用于查某个目标l=0，r=n-1；while(l<=r)l=mid+1 或 r=mid-1

right=mid 为什么保留了正确答案？

本模板把 [left,right) 看成尚未分类的元素，而目标是它们之间的分界位置。a[mid]≥x 时，mid 这个元素已经可以归入右侧已知区域；分界仍可能正好位于 mid，所以用 right=mid。把 right 改成 mid-1 可能跨过正确分界。

终止的度量是 right-left。只要 left<right，就有 left≤mid<right；right=mid 必然让 right 变小，left=mid+1 必然让 left 变大。因此每轮剩余长度严格下降，不存在停在原地的情况。

保持 [0,left) 中所有值 < x，[right,n) 中所有值 >= x，未知区域为 [left,right)。当未知区域为空时 left 就是唯一边界。

手推一个例子

[1,2,2,5] 查找 2：初始 [0,4)，mid=2 满足条件，right=2；mid=1 满足，right=1；mid=0 不满足，left=1，返回 1。

C++17
下载 .cpp
int lowerBound(const vector<int>& a, int x) {
    int left = 0, right = (int)a.size();
    while (left < right) {
        int mid = left + (right - left) / 2;
        if (a[mid] >= x) right = mid;
        else left = mid + 1;
    }
    return left; // 允许等于 a.size()，表示所有元素都小于 x
}
复杂度
时间 O(log(n+1))，额外空间 O(1)。输入必须按非降序排列。
易错点与边界
闭区间与半开区间模板不能拼接使用。返回下标等于 n 时不可直接读取 a[index]。

3.4 上界二分：把“≥”变成“>”意味着什么？

新的不变量是 [0,left) 全部≤x，[right,n) 全部>x。比如 [1,2,2,5] 查 2，lowerBound=1、upperBound=3，二者差 2 就是出现次数。最后一个≤x 的下标为 upperBound-1，但上界为 0 时不存在这样的元素。

int upperBound(const vector<int>& a, int x) {
    int left = 0, right = (int)a.size();
    while (left < right) {
        int mid = left + (right - left) / 2;
        if (a[mid] > x) right = mid;
        else left = mid + 1;
    }
    return left; // 第一个 >x 的位置；可能为 n
}

3.6 归纳法与交换论证分别怎么用？

递归正确性常用归纳法。以归并排序为例：长度≤1 时已经有序；假设更短的两半排序正确，合并时每次取两半当前最小者，即得到整个区间的最小未输出值，最终完整有序。必须同时证明递归规模缩小到基例。

贪心常用交换论证。区间调度选择最早结束区间：从任意最优解出发，把它第一个区间替换为结束更早或相同的贪心区间，不会挤占后续区间，数量也不减少。因此存在包含该贪心选择的最优解，然后递归处理剩余任务。

不同问题需要不同证明，不能只说“用了贪心所以最优”或“试了很多样例所以正确”。样例用于检验，证明用于覆盖未枚举的所有合法输入。

面试追问：关键点完整解答

为什么 right=mid 不会死循环？

循环条件保证 left<right，向下取整的 mid 严格小于 right。right=mid 会缩短区间；另一分支 left=mid+1 也会缩短。错误的 left=mid 才可能在 right=left+1 时停住。

如何改成第一个大于 x 的位置？

把条件 a[mid]>=x 改成 a[mid]>x，其余更新保持一致。与此同时，把左侧不变量改为≤x，右侧改为>x，不能只改符号却继续使用旧证明。

为什么 mid=left+(right-left)/2 更稳妥？

在 0≤left≤right≤INT_MAX 前提下，right-left 不溢出，而且结果介于 left 与 right 之间；直接 left+right 可能先溢出。如果允许任意带符号端点，right-left 本身也可能溢出，需要另选更宽类型或适当的中点算法。

答案二分与数组二分有何共同点？

都在找一个单调谓词从 false 到 true 的分界。数组里是 a[i]>=x；运输能力题可以是“容量 cap 能否在 D 天内送完”。必须先证明 check 随候选值单调，再决定搜索方向。

测试通过为什么不等于正确？

有限测试没有穷尽输入。证明中若遗漏“数组有序”“字符集”“非负权”等前提，正常样例仍可能通过。主动找最小反例，并用不变量覆盖所有合法输入。

4.1 数值范围先算清：类型由结果上界决定

常见平台的 int 是 32 位，范围约为 −2.147×10⁹ 到 2.147×10⁹；long long 至少 64 位。若 n≤10⁵、|a[i]|≤10⁹，区间累计值可能到 10¹⁴，int 明显不够。返回值、累加器和中间表达式都要一起审查。

C++ 的有符号整数溢出是未定义行为，不应依赖“它会绕回负数”。无符号整数按模 2ʷ 运算虽然有定义，但不代表它符合题目的数学含义。

先提升类型，再执行乘法与累加

若 a=b=1000000000，a*b 会先按 int 运算，即使外面写 (long long)(a*b) 也已经太晚；1LL*a*b 才把整个后续乘法链提升。这里两个 int 的乘积可由常见 64 位 long long 容纳，更多因子的乘积仍需独立估算上界。

4.4 两种输入输出模式，以及为什么要关闭同步

函数模式通常由平台提供 main 和调用数据，只提交指定函数/类；ACM 模式需要自己处理 main、输入、输出格式和多组测试。返回了正确值却没有按要求打印，也可能判错。

ios::sync_with_stdio(false) 关闭 C 与 C++ 标准流之间的同步；cin.tie(nullptr) 解除读取前自动刷新 cout 的绑定。普通离线题常在首次 I/O 之前设置这两项，之后避免交错混用 printf/scanf 与 cin/cout。交互题可能需要主动 flush。

'\n' 只表示换行；endl 表示换行并刷新缓冲区。大量逐行输出时通常优先 '\n'。若先用 cin>>n 再 getline(cin,line)，需处理遗留换行；如果允许空行或前导空格，不要不加区分地用 ws 把它们吞掉。

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    if (!(cin >> n) || n < 0) return 0;
    long long sum = 0;
    for (int i = 0; i < n; ++i) {
        long long x;
        if (!(cin >> x)) return 0;
        sum += x; // 题目需保证总和在 long long 范围内

    cout << sum << '\n';
    return 0;
}

4.5 实战解题流程：先把要求变成可检查的规格

第一步确认：输入是否为空、是否有序、能否修改、值域与数据规模、重复值是否允许、返回的是下标还是值、求数量还是一个解、无解如何表示。第二步手推一个一般样例和一个边界样例。

第三步写出可靠的暴力解，找清时间瓶颈是重复求和、重复查找还是重复子问题。第四步利用条件优化：重复区间和可用前缀和，重复查询可用哈希，单调边界可用二分，重叠状态可用 DP。

面试追问：关键点完整解答

什么时候使用 const vector<int>&？

函数只读输入且不需要拥有独立副本时使用它，例如查询、遍历、统计。需要改变原数组时用非 const 引用；刻意保留原数组并对副本排序时可以按值传递，同时把复制成本计入复杂度。

为什么 1LL*a*b 比 (long long)(a*b) 更安全？

表达式从子表达式开始计算。后一种先做 int×int，溢出发生后再转换无济于事；前一种先做 long long×int，随后仍以 long long 运算。是否足够安全仍取决于 long long 能否容纳最终结果。

accumulate 为什么要写 0LL？

累加器类型由第三个参数的类型决定。初值 0 是 int，即使函数最终返回 long long，中间累加也可能先溢出；0LL 把累加器指定为 long long。

size_t 和 int 混用为什么危险？

size_t 是无符号类型。在常见比较规则下，负的 int 可能被转成巨大的无符号值；size()-1 对空容器也会先在无符号类型中下溢。已知长度≤INT_MAX 时先转 int 再做带负值的下标运算，或采用安全的迭代器写法。

reserve(n) 后能直接写 a[n-1] 吗？

不能。reserve 只改变容量，不创建元素；有效下标仍由 size 决定。需要先 resize(n)，或者逐次 push_back。

如何回答代码的测试情况？

准确区分“做过桌面推演”“编译通过”“指定用例运行通过”“随机差分测试通过”。编译只检查语法与部分类型错误，不能证明结果正确；也不要声称运行了没有实际执行的测试。

综合例题：把多次区间求和，从暴力推到前缀和

题意：给定 n 个整数和 q 次查询，每次查询闭区间 [l,r] 的和，数组不会修改，下标从 0 开始。假设 n,q≤10⁵、|a[i]|≤10⁹。先明确“不修改”这个条件：它允许一次预处理服务所有查询。

暴力方案每次扫描 [l,r]，最坏 O(nq)，可能有 10¹⁰ 次累加。重复工作是相邻查询反复计算相同前缀，因此定义 pre[k] 为前 k 个元素之和，pre[0]=0；查询答案 pre[r+1]-pre[l]，两个前缀的共同部分正好抵消。

预处理不变量：完成第 i 轮后，pre[i+1] 等于 a[0]..a[i] 的和。初始化 pre[0]=0 成立；用 pre[i+1]=pre[i]+a[i] 保持；终止后全部前缀正确。总时间 O(n+q)、额外空间 O(n)，累计范围需要 long long。

class PrefixSum {
    vector<long long> pre;
public:
    explicit PrefixSum(const vector<int>& a) : pre(a.size() + 1, 0) {
        for (size_t i = 0; i < a.size(); ++i) pre[i + 1] = pre[i] + a[i];
    }
    long long query(int l, int r) const {
        // pre.size()=n+1；合法 r 满足 r<n。
        if (l < 0 || r < l || (size_t)r >= pre.size() - 1)
            throw out_of_range("invalid closed interval");
        return pre[(size_t)r + 1] - pre[l];
    }
};
int main() {
    PrefixSum p({2, -1, 3, 4});
    assert(p.query(1, 3) == 6);
    assert(p.query(0, 3) == 8);
    assert(p.query(0, 0) == 2);
    assert(p.query(1, 1) == -1);

    PrefixSum large({1000000000, 1000000000, 1000000000});
    assert(large.query(0, 2) == 3000000000LL);

    bool rejected = false;
    try { PrefixSum empty({}); empty.query(0, 0); }
    catch (const out_of_range&) { rejected = true; }
    assert(rejected);
    cout << "prefix tests passed\n";
}

如果面试官改了条件，该怎么回答？

若只有一次查询，直接求和 O(n) 更简单，前缀和不会带来渐近优势。若查询之间频繁修改数组，普通前缀和更新最坏 O(n)，应考虑第 13 章的树状数组或线段树。若只要求流式总和，根本不需要保存整个数组。数据结构取决于操作组合，而非题目出现“求和”两个字。

章末自测：先回答，再对照解析

外层 i 每次翻倍，内层从 0 执行到 i-1，总时间是多少？

假设 i=1,2,4,…<n，工作量为 1+2+4+…<2n，所以 Θ(n)，不是 Θ(n log n)。若内层每轮固定扫描 n 次，才是 Θ(n log n)。

一个 O(n) 的循环，每轮复制长度 n 的字符串，整体还是 O(n) 吗？

不是。字符串复制是 O(n)，n 轮总计 O(n²)。若副本每轮销毁，峰值额外空间可以只有 O(n)，不能再把空间误加成 O(n²)。

二叉树有 n 个节点，递归遍历空间一定是 O(n) 吗？

最坏 O(n)，更准确为 O(h)。平衡树 h=O(log n)，链状树 h=n；总节点数决定访问时间，树高决定活跃递归深度。

两个独立数组长度 n、m，分别遍历后排序第一个，总时间是什么？

O(n+m+n log n)，通常简写为 O(n log n+m)。不能在不知道 m 与 n 关系时省略 m。

“哈希表是 O(1)，所以整个算法最坏 O(n)”对吗？

不严谨。常见无额外保障的哈希表查询平均 O(1)、单次最坏 O(n)；n 次操作平均 O(n)，最坏可能 O(n²)。需要按实际容器保证与问题要求表述。

前缀和为什么多开一个位置？

pre[0] 表示空前缀，从 l=0 开始的查询也可统一写 pre[r+1]-pre[l]，无需访问 pre[-1] 或另写特判。

只有一个元素时，lowerBound 的 while 会执行几次？

恰好一次：left=0、right=1、mid=0。若元素≥x，right=0；否则 left=1。两种情况立即结束。空数组执行零次。
