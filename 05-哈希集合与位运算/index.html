05.01

哈希映射：存在、下标还是次数

知识与适用场景

哈希表的 value 必须服务于问题目标：判断存在用 set，返回位置保存下标，统计数量保存频次，求最长区间常保存最早下标。键必须能完整代表你要比较的状态。

1.1 平均 O(1) 的来源与边界

unordered_map 通常将哈希值映射到桶，然后用键的相等比较找到目标。不同键可进入同一桶，这叫冲突，不代表答案错误；正确性依赖相等比较，而不依赖哈希值唯一。桶分布良好且负载受控时，查找、插入、删除平均 O(1)，极端冲突可退化为 O(n)。

因此 n 次操作平均 O(n)、最坏可能 O(n²)。reserve 可减少扩容带来的重哈希，但不能消灭冲突或把复杂度变成最坏 O(1)。需要确定性上界时可以考虑排序加扫描或有序树，代价常为 O(n log n)。字符串和数组键还要计入构造、计算哈希及比较键的成本。

1.3 两数之和：表中只保存严格早于 i 的元素

扫描下标 i 之前，pos 中每个位置都小于 i。先查 target-a[i]，命中后与当前 i 组成两个不同下标；再保存 a[i]。如果先写入当前元素，a[i]*2=target 时可能把自己使用两次。

基础示例 target 是 long long，但宽类型仍有范围。本章将两数之和及前缀示例约定为 n<=100000、|a[i]|<=10^9、|target|或|k|<=10^14；如此差值和前缀计算均在 long long 内。若允许任意 LLONG_MIN/LLONG_MAX 参数，须另外检查减法溢出，不能认为 long long 永远安全。

若要求所有下标对，value 改成历史下标列表，每次查询将列表中的 j 与 i 输出，然后追加 i。总时间应写平均 O(n+输出对数)，全为0且target=0时有 n(n-1)/2 个答案，任何完整输出算法都不能是 O(n)。

1.5 自定义键：相等就必须有相同哈希

规则是 key_equal(a,b) 为真时 hash(a)==hash(b)。反方向不要求成立；两个不同键有相同哈希是合法冲突，容器会继续检查相等性。若只把一个短哈希值作为真正的键而丢弃原状态，就失去了这一步校验，可能错误合并对象。

异位词可以用排序后的字符串作键，也可以用26维频次作键。用无分隔数字直接拼接会有歧义，例如两格计数 (1,11) 与 (11,1) 都能变成111。下面直接使用 array<int,26>，其相等比较保留了完整信息。

1.6 字母异位词分组：完整频次键与稳定的组顺序

前提：每个词长度<=100000，只允许小写 a-z。该哈希只是教学实现，不是抗恶意冲突的安全哈希。桶冲突由完整数组相等比较区分，不会错误分组。

平均时间 O(L+26m)，L为总字符数、m为词数；最坏冲突时查找可退化到 O(26m²)，另加读入字符成本。结果按每个组首次出现顺序排列、组内保持输入顺序；这是由 result 控制的，不是依赖哈希表遍历顺序。空字符串的键全为0，可以正常成组。

struct LetterCountsHash {
    size_t operator()(const array<int, 26>& key) const noexcept {
        size_t hash = 0;
        for (int count : key)
            hash = hash * size_t{131} + static_cast<size_t>(count);
        return hash; // unsigned overflow is defined; collisions are allowed
    }
};
vector<vector<string>> groupAnagrams(const vector<string>& words) {
    unordered_map<array<int, 26>, size_t, LetterCountsHash> groups;
    groups.reserve(words.size());
    vector<vector<string>> result;
    for (const string& word : words) {
        array<int, 26> key{};
        for (char ch : word) {
            if (ch < 'a' || ch > 'z')
                throw invalid_argument("lowercase a-z required");
            ++key[ch - 'a'];
        }
        auto [it, inserted] = groups.emplace(key, result.size());
        if (inserted) result.push_back({});
        result[it->second].push_back(word);
    }
    return result;
}
推导 / 不变量

两数之和先查询补数，再插入当前数，保证不会重复使用同一个位置。此前所有元素都在表中，因此当前元素作为较晚端点的解不会被遗漏。

手推一个例子

[3,3]，target=6：第一个 3 只入表；第二个 3 查到下标 0，返回 [0,1]。若先插入当前值，可能错误得到同一个下标两次。

vector<int> twoSum(const vector<int>& a, long long target) {
    unordered_map<long long, int> pos;
    for (int i = 0; i < (int)a.size(); ++i) {
        auto it = pos.find(target - a[i]);
        if (it != pos.end()) return {it->second, i};
        pos[a[i]] = i;
    }
    return {};
}

bool isIsomorphic(const string& s, const string& t) {
    if (s.size() != t.size()) return false;
    array<int, 256> forward, backward;
    forward.fill(-1); backward.fill(-1);
    for (size_t i = 0; i < s.size(); ++i) {
        unsigned char a = static_cast<unsigned char>(s[i]);
        unsigned char b = static_cast<unsigned char>(t[i]);
        if (forward[a] == -1 && backward[b] == -1) {
            forward[a] = b; backward[b] = a;
        } else if (forward[a] != b || backward[b] != a) {
            return false;
        }
    }
    return true;
}

1.8 前缀和+哈希：从等式反推查找的键

定义 P[0]=0、P[i] 为前 i 个数之和。区间 [j,i) 的和为 P[i]-P[j]。要让区间和等于 K，只需查 P[j]=P[i]-K。扫描每个右端点 i，用一张表汇总此前的 P[j]，就能避免枚举所有 j。

求数量时，同一前缀出现几次就贡献几个区间；求最长时，只要知道同一前缀出现得最早的位置。两个任务的键相同，value 与更新规则不同。负数不妨碍等式成立，所以这套方法不依赖正数滑动窗口的单调性。

1.9 和为 K 的子数组计数：先查询，再增加当前前缀

约定 n<=100000、|a[i]|<=10^9、|k|<=10^14。frequency[0]=1 表示数组之前的空前缀，而不是把空子数组计为答案；查询时表中只有更早前缀，确保区间非空。

全为0的长度n数组、K=0时答案 n(n+1)/2，需 long long。时间平均 O(n)、最坏 O(n²)，空间 O(n)。用 find 查询不会插入不存在的补数；递增 frequency[prefix] 则有意使用 operator[]。

long long countSubarraysWithSum(const vector<int>& a, long long k) {
    unordered_map<long long, long long> frequency;
    frequency[0] = 1;
    long long prefix = 0, answer = 0;
    for (int value : a) {
        prefix += value;
        auto it = frequency.find(prefix - k);
        if (it != frequency.end()) answer += it->second;
        ++frequency[prefix];
    }
    return answer;
}

1.11 和为 K 的最长子数组：只保留首次位置

采用与计数示例相同的数值约束。P[0] 的位置是0，长度直接为 i-j；也可用元素下标-1表示初始前缀，但不能混用两种下标定义。平均 O(n)、最坏 O(n²)、空间 O(n)。

int longestSubarrayWithSum(const vector<int>& a, long long k) {
    unordered_map<long long, int> first;
    first.emplace(0, 0); // prefix index, not element index
    long long prefix = 0;
    int best = 0;
    for (int i = 1; i <= (int)a.size(); ++i) {
        prefix += a[i - 1];
        auto it = first.find(prefix - k);
        if (it != first.end()) best = max(best, i - it->second);
        first.emplace(prefix, i); // do not overwrite earlier occurrence
    }
    return best;
}

1.12 子数组和可被 K 整除：规范化负余数

P[i]-P[j] 能被 K 整除等价于两者同余。C++ 中 -1%5 是-1而不是4，必须把余数规范到 [0,K-1]，否则会漏掉等价状态。示例 [-1,5]、K=5 中两个后续前缀都规范为4，计出 [5]。

只维护余数而不累计完整前缀：remainder+value 以 long long 计算，int 输入不会导致这一步溢出；约定 n<=100000，计数放 long long。平均 O(n)，额外空间 O(min(n+1,K))；若 K 小而固定，vector<long long>(K) 常更直接。

long long countDivisibleSubarrays(const vector<int>& a, int k) {
    if (k <= 0) throw invalid_argument("k must be positive");
    unordered_map<long long, long long> frequency;
    frequency[0] = 1;
    long long remainder = 0, answer = 0;
    for (int value : a) {
        remainder = (remainder + value) % k;
        if (remainder < 0) remainder += k;
        auto it = frequency.find(remainder);
        if (it != frequency.end()) answer += it->second;
        ++frequency[remainder];
    }
    return answer;
}

面试追问：关键点完整解答

如果两数之和要返回所有下标对，应该怎么改？

值映射到历史下标列表；当前补数命中时输出列表中每个下标与当前下标，再把当前下标追加进去。先查后写避免使用自己。复杂度要包含输出规模：全0输入会产生二次量级的下标对。

为什么不能把前缀频次表换成 unordered_set？

集合只知道某个前缀出现过，无法知道有几个不同起点。[1,-1,1] 的前缀0出现两次，最后一个右端点会贡献两个答案；集合只能贡献一个，造成漏计。

frequency[0]=1 与 first[0]=0 各代表什么？

两者都代表数组之前的空前缀P[0]。前者保存次数1，后者保存位置0。这样从第一个元素开始的合法区间无需特判；它们的 value 语义不同，不能机械互换。

计数时先 ++frequency[prefix] 再查询会怎样？

K=0时会把当前前缀与自己配对，计入长度0的空区间。表中必须只存严格早于当前右端点的前缀。先查后写维护了这一时间边界。

两个不同键的哈希值相同是否会错误合并？

正确的 unordered_map 不会：哈希定位候选桶后还要比较完整键。若自己只保留哈希摘要作为真正键，则没有完整状态可供复核，才可能把冲突误认为相等。

最长区间遇到同一个前缀，为什么不更新为最新位置？

对未来固定的右端点i，较早的j使i-j更大。覆盖掉最早位置会丢失可能的最优解。使用 emplace 保持首次位置；求最短或最近距离时，更新策略可能恰好相反。

05.02

集合：最长连续序列为何是线性

知识与适用场景

把所有数放进集合后，仅从没有前驱 x-1 的数启动向后扩展。这保证每段连续区间只被扫描一次，而不是对每个起点重复扫描整段。

2.1 集合是去重后的状态空间，不是有序数组

unordered_set 表示存在性，不保存次数和位置，也不保证按数值或插入顺序遍历。需要有序输出时，显式排序答案；需要重复次数时用 map<值,次数> 的思路或 unordered_map，不能把信息丢掉后再试图恢复。

固定且较小的整数取值域可用布尔数组、计数数组或位集合替代哈希。例如只含小写字母的成员判断用26位即可；但范围大且稀疏时，按最大值分配数组会浪费内存。

2.2 最长连续序列：一次分块，而不是每个数都试着扩展

先将输入去重。从一个值 x 开始向右搜索前，检查 x-1 是否存在；存在就跳过，因为 x 位于某个连续块内部。只有块的最小值会启动搜索，且会把该块完整扫描一次。

若有 m 个不同数和 c 个连续块，外层前驱查询m次；各块成功扩展总计m次，终止失败查询c次，所以哈希查询总数 O(m)。再加构建集合 O(n) 次插入，平均 O(n)、最坏 O(n²)，额外空间 O(m)。这不是依赖“看起来循环没跑很多”，而是将操作分摊到互不重叠的连续块。

2.4 两个常见的伪线性写法

第一种：从每个不同值都向右扩展。输入1..m时，总扩展次数为m+(m-1)+…+1，退化为O(m²)。第二种：虽然检查了前驱，但外层遍历原数组；若最小值1重复r次，后面又有2..m，每个1都会启动长度m的扩展，总O(rm)。

基础代码外层遍历去重集合，因此没有上述重复。集合存 long long、输入为 int，所以 x-1、y++ 不会在 INT_MIN 或 INT_MAX 附近发生有符号溢出。不要把相同代码直接推广到任意 long long 极值输入而不加保护。

推导 / 不变量

集合去重后，连续块只有一个最小值能触发扩展。扫描集合一次，加上各块内总共 O(n) 次扩展，平均总成本 O(n)。

2.7 距离不超过 K 的重复元素：只保留最近 K 个位置的集合

查询a[i]之前，集合代表下标[max(0,i-k),i-1]中的值。相等下标之间距离至多K就能命中；注意移出的是i-k-1，不是仍应保留的i-k。

为什么集合不需要计数？只要窗口里出现重复就已经返回true，能够继续执行的窗口必然没有重复，因此删除一个旧值不会误删另一个仍有效的同值。若改成统计所有重复或不提前返回，则要重新考虑频次。平均时间O(n)，辅助空间O(min(n,K+1))。

bool containsNearbyDuplicate(const vector<int>& a, int k) {
    if (k <= 0) return false;
    unordered_set<int> window;
    for (int i = 0; i < (int)a.size(); ++i) {
        if (i > k) window.erase(a[i - k - 1]);
        if (window.find(a[i]) != window.end()) return true;
        window.insert(a[i]);
    }
    return false;
}

面试追问：关键点完整解答

最长连续序列的连续，是下标连续还是数值连续？

要求数值能排列为x,x+1,…，不要求它们在原数组相邻，也不保留原顺序。因此可去重后用集合；若题目要求原数组中的连续子数组，就不能用这套方法。

为什么集合遍历顺序随机也不影响最长连续序列？

是否启动只由前驱存在性决定，与遍历时间顺序无关；集合在扫描期间保持不变。无论何时访问一个块的最小值，都能沿成员查询遍历完整块。

嵌套 while 的线性证明是什么？

只有每个连续块的最小值进入while；不同连续块没有重叠，每个不同元素只会作为成功扩展被访问一次。加上前驱查询与各块结束的失败查询，总查询次数线性；哈希单次成本仍只是平均常数。

交集为什么要先确认是唯一交集还是多重交集？

两者对重复的定义不同。a=[2,2]、b=[2,2,2]，唯一交集是[2]，多重交集是[2,2]。集合只保留存在性，丢掉了计算多重交集所需的次数信息。

能一边 range-for 遍历 unordered_set，一边插入吗？

插入可能引发rehash而使当前迭代器失效，不应这样写。读取阶段与修改阶段分开最稳妥；删除当前项时可采用显式迭代器 it=container.erase(it)。rehash通常不使未删除元素的引用和指针失效，但不能因此继续使用旧迭代器。

附近重复题中，距离恰好 K 的元素应该移除吗？

不应该。当前位置i仍应与i-K比较，过期的是下标小于i-K的元素。本例每次删除i-K-1，再查询当前值；[1,2,1]、K=2应返回true，K=1应返回false。

异或与二进制计数

知识与适用场景

异或满足交换律、结合律，且 x^x=0，因此偶数次出现的元素会抵消。但不能把这个结论套到出现三次的问题，后者需要按位计数或状态机。

3.1 先明确按位与逻辑，再写表达式

&、|、^ 对整数的每个二进制位操作；&&、|| 将表达式按真假求值且具有短路行为。例如2&1为0，2&&1为true。~是按位取反，!是逻辑非；~0不是一个只包含业务范围内有效位的集合。

运算优先级常导致误读。判断某位是否为0，写 (x & mask)==0，不要写 x & mask==0，后者按 x & (mask==0) 解释。即使能背优先级，面试代码也应主动加括号。

3.5 异或消去：答案由出现次数的奇偶决定

按位看，异或是在模2意义下相加，相同位出现偶数次变0，奇数次保留。一个元素出现一次、其余各出现两次时，所有重复项成对消去，留下单次元素。其实“其余出现偶数次”就足够；若其他元素也出现奇数次，结果会混入它们。

异或不是计数器：它不能区分出现1次、3次或5次。数组为空时归约得到0也不能证明0是单次答案；题目对元素次数与存在性的保证是解法的一部分。

pair<uint32_t, uint32_t> twoSingleNumbers(const vector<uint32_t>& a) {
    uint32_t combined = 0;
    for (uint32_t value : a) combined ^= value;
    if (combined == 0) throw invalid_argument("required distinct singles missing");
    uint32_t split = combined & (uint32_t{0} - combined);
    uint32_t first = 0, second = 0;
    for (uint32_t value : a) {
        if ((value & split) == 0) first ^= value;
        else second ^= value;
    }
    return {first, second};
}

3.8 其他数字出现三次：逐位计数模3

对每个二进制位，所有出现三次的数字总贡献都是3的倍数；取模3后只留下单次数字在该位的0或1。逐位恢复即可，不需要假设数值大小能被普通异或区分。

进阶可用ones、twos两个掩码实现每一位的三态计数器，但更新顺序容易错。先掌握32次扫描的直观证明；固定32位下O(32n)=O(n)，多一个常数并不会改变渐近复杂度。

int32_t singleAmongTriples(const vector<int32_t>& a) {
    uint32_t bits = 0;
    for (unsigned bit = 0; bit < 32; ++bit) {
        int remainder = 0;
        for (int32_t value : a) {
            uint32_t u = static_cast<uint32_t>(value);
            remainder = (remainder + int((u >> bit) & uint32_t{1})) % 3;
        }
        if (remainder != 0) bits |= uint32_t{1} << bit;
    }
    int64_t signedValue = bits;
    if ((bits & (uint32_t{1} << 31)) != 0)
        signedValue -= (int64_t{1} << 32);
    return static_cast<int32_t>(signedValue);
}

练习：LeetCode 136 只出现一次的数字、260 只出现一次的数字 III、191 位 1 的个数。

面试追问：关键点完整解答

为什么 x&(x-1) 恰好删除最低位的1？

把x写成高位前缀、一个最低1、若干尾随0。减1会将该1变0、尾随0变1，而更高前缀不变；相与后高位保留，原来的最低1清零，其右边仍为0。因此1的数量恰少一个。

x&-x 为什么在有符号代码里有风险？

有符号最小值的相反数无法在同类型表示，-INT_MIN可能溢出。无符号类型用0-x具有明确的模2^w语义，x&(0-x)才能安全覆盖最高位单独为1的情况。

异或能不能解决其他数出现三次？

不能直接归约。x^x^x=x，不会抵消；需要逐位计数模3或对应状态机。异或解法适用于其他数出现偶数次的消去模型，而不是任意重复次数。

两个单次数字为何一定能被lowbit分开？

它们不同，所以异或a^b不为0。异或结果中任一为1的位，恰好表示a、b该位不同；按该位分组时两者必定进入不同组，而每一对相同数字仍进入同一组并抵消。

为什么 1ULL<<64 仍不合法？

即使左操作数是64位，合法移位量也只有0到63。类型足够存一个结果，不代表可以按位宽本身移位。若要构造64位全1，使用~uint64_t{0}而不是(1ULL<<64)-1。

把负数强转为无符号会丢掉信息吗？

转换按模2^w定义，可用于固定宽度位模式处理。问题在于把超范围无符号结果直接转回有符号在C++17中是实现定义行为；本节先在更宽的int64_t中减去2^32，使结果落在int32_t范围内，再转换。

知识与适用场景

n 个选或不选状态可用 n 位二进制编码，第 i 位为 1 表示选择第 i 个元素。这适合 n 较小的穷举、状态压缩 DP 和集合运算。

4.1 位掩码表示的是下标集合

给n个对象编号0..n-1，第i位为1表示选择对象i。不同整数在n位内有不同位模式，因此与下标子集一一对应；空集为0，全集为(1<<n)-1，但构造全集前必须确认移位类型与n的范围。

输入[a,b,c]中101表示选择下标0和2。若输入[1,1]，01和10是不同下标集合，但得到的值列表都为[1]。按位枚举本身不去除值重复；题目要求不同值子集时，需要排序加回溯去重或另行设计规范状态。

n位可编码2^n个子集，但枚举所有子集仍需指数时间。逐个输出元素的总次数为n*2^(n-1)（n>=1），所以完整返回所有子集的时间和输出空间通常为O(n*2^n)，不能只写O(2^n)。

基础示例把n限制在20，只是防止显然不可行的指数输出，并不保证n=20就适合所有内存限制。上百万个vector的对象开销、每个子集的分配开销和元素存储都要算入。只需要统计或求最优值时，可边枚举边处理，不必把所有子集保存下来。

4.4 子掩码转移：为什么 (sub-1)&mask 不会漏

从sub=mask开始。sub-1会清除当前最低1并把其右侧位全部变成1，再与mask相与，删掉不属于全集mask的位，于是得到严格小于sub的最大合法子掩码。反复执行就会按数值递减枚举每个子掩码一次。

非空枚举写for(sub=mask;sub;sub=(sub-1)&mask)。若要包含空集，必须在处理sub==0后break；对无符号sub而言，0-1会回绕为全1，再与mask得到mask，不退出就无限循环。

4.7 快速幂：二进制按位拆分指数

指数e的第i位为1，就需要乘入base^(2^i)。每轮检查最低位，必要时乘入答案；然后将base平方、e右移。循环不变量是 result*currentBase^remaining 等于原来的base^exponent（模mod意义下）。

4.8 模快速幂：限定模数以保证乘法不溢出

乘法两端已规范到[0,mod-1]，限制mod<=10^9+7后，乘积最多约10^18，小于LLONG_MAX。只在乘完后取模并不能修复已经发生的溢出；若放宽mod范围，应使用安全模乘算法，或在允许的编译器上使用更宽整数扩展。

long long modularPower(long long base, uint64_t exponent, long long mod) {
    if (mod <= 0 || mod > 1000000007LL)
        throw invalid_argument("require 1 <= mod <= 1000000007");
    base %= mod;
    if (base < 0) base += mod;
    long long result = 1 % mod;
    while (exponent != 0) {

        base = base * base % mod;
        exponent >>= 1;
    }
    return result;
}

4.9 状态压缩DP入门：n个人分配n个任务

cost[i][j]表示第i个人承担任务j的费用，每个人与每个任务恰好出现一次。定义dp[mask]：已经将mask中的任务分配给前popcount(mask)个人时的最小费用。当前已分配人数k由mask唯一确定，不需要再加一维存k。

从dp[mask]出发，选一个未使用任务j，转移到mask|(1<<j)，新费用dp[mask]+cost[k][j]。初始dp[0]=0；答案dp[(1<<n)-1]。每次增加一个1，数值严格变大，按mask递增遍历是合法拓扑顺序。

正确性来自最后一步分解：任何可行方案都能删掉当前最后分配的人与任务，回到一个更小的合法状态；枚举所有未使用任务覆盖所有方案，再取最小不会漏掉最优。这里是状态建模演示，规模大时可用匈牙利算法等多项式方法。

4.10 最小费用任务分配：O(n·2^n) 状态压缩

long long minimumAssignmentCost(const vector<vector<int>>& cost) {
    int n = (int)cost.size();
    if (n > 20) throw invalid_argument("n must not exceed 20");
    for (const auto& row : cost) {
        if ((int)row.size() != n) throw invalid_argument("square matrix required");
        for (int value : row)
            if (value < 0 || value > 1000000000)
                throw invalid_argument("cost outside supported range");
    }
    size_t total = size_t{1} << n;
    const long long INF = LLONG_MAX / 4;
    vector<long long> dp(total, INF);
    dp[0] = 0;
    for (size_t mask = 0; mask < total; ++mask) {
        int person = 0;
        for (size_t bits = mask; bits != 0; bits &= bits - 1) ++person;
        if (person == n || dp[mask] == INF) continue;
        for (int job = 0; job < n; ++job) {
            size_t bit = size_t{1} << job;
            if ((mask & bit) != 0) continue;
            size_t next = mask | bit;
            dp[next] = min(dp[next], dp[mask] + cost[person][job]);
        }
    }
    return dp.back();
}

面试追问：关键点完整解答

n=40能放进uint64_t，为什么还不能枚举全部子集？

可编码不等于可遍历。2^40约为一万亿个状态，完整枚举时间已经不可接受，若返回所有子集还要更大存储。需要利用其他结构、剪枝、折半搜索或改变算法，而不是只换整数类型。

~mask为什么不等于业务集合的补集？

按位取反会翻转整个整数宽度，包括没有分配给业务对象的高位。必须用全集U进行截断：U&~mask。若mask本来就是U的子集，U^mask也等价。

sub枚举到0后继续更新会怎样？

无符号0-1回绕为全1，(sub-1)&mask重新变成mask，于是从头循环。包含空集的写法应在处理0后立刻break；非空枚举则直接把sub!=0作为条件。

为什么枚举所有mask的所有sub是3^n？

对每个元素分别选择：不在mask；在mask但不在sub；同时在mask和sub。n个元素独立选择得到3^n种(mask,sub)组合，等于所有子掩码枚举次数之和。

快速幂为什么仍需考虑乘法溢出？

取模发生在乘法之后，若有符号乘法先越界，结果已经不合法，后续%无法补救。本例限制模数保证乘积能用long long表示；更大模数需要安全模乘。

任务分配DP为什么不再存person这一维？

在该模型中，每一步恰好分配一个任务给下一个人，所以已分配人数恰等于mask的1的个数，person完全由mask决定。若模型允许跳过人员或一次分配多个任务，就必须重新评估状态是否仍包含足够信息。

long long countSubarraysWithSum(const vector<int>& a, long long k) {
    unordered_map<long long, long long> frequency;
    frequency[0] = 1;
    long long prefix = 0, answer = 0;
    for (int value : a) {
        prefix += value;
        auto it = frequency.find(prefix - k);
        if (it != frequency.end()) answer += it->second;
        ++frequency[prefix];
    }
    return answer;
}

int longestSubarrayWithSum(const vector<int>& a, long long k) {
    unordered_map<long long, int> first;
    first.emplace(0, 0); // prefix index, not element index
    long long prefix = 0;
    int best = 0;
    for (int i = 1; i <= (int)a.size(); ++i) {
        prefix += a[i - 1];
        auto it = first.find(prefix - k);
        if (it != first.end()) best = max(best, i - it->second);
        first.emplace(prefix, i); // do not overwrite earlier occurrence
    }
    return best;
}

bool containsNearbyDuplicate(const vector<int>& a, int k) {
    if (k <= 0) return false;
    unordered_set<int> window;
    for (int i = 0; i < (int)a.size(); ++i) {
        if (i > k) window.erase(a[i - k - 1]);
        if (window.find(a[i]) != window.end()) return true;
        window.insert(a[i]);
    }
    return false;
}

pair<uint32_t, uint32_t> twoSingleNumbers(const vector<uint32_t>& a) {
    uint32_t combined = 0;
    for (uint32_t value : a) combined ^= value;
    if (combined == 0) throw invalid_argument("required distinct singles missing");
    uint32_t split = combined & (uint32_t{0} - combined);
    uint32_t first = 0, second = 0;
    for (uint32_t value : a) {
        if ((value & split) == 0) first ^= value;
        else second ^= value;
    }
    return {first, second};
}

int32_t singleAmongTriples(const vector<int32_t>& a) {
    uint32_t bits = 0;
    for (unsigned bit = 0; bit < 32; ++bit) {
        int remainder = 0;
        for (int32_t value : a) {
            uint32_t u = static_cast<uint32_t>(value);
            remainder = (remainder + int((u >> bit) & uint32_t{1})) % 3;
        }
        if (remainder != 0) bits |= uint32_t{1} << bit;
    }
    int64_t signedValue = bits;
    if ((bits & (uint32_t{1} << 31)) != 0)
        signedValue -= (int64_t{1} << 32);
    return static_cast<int32_t>(signedValue);
}

        long long sum = 0;

章末自测与完整解答

1. [3,3]、target=6为什么不能先插入当前值？

先插入会使补数查询直接命中当前下标，可能返回同一个元素两次。先查后插，在处理第二个3时返回下标0和1，保持历史位置严格早于当前位置。

2. 三个0中，和为0的非空子数组一共有多少？

有3个长度1、2个长度2、1个长度3，共6个。前缀0的历史次数依次为1、2、3，每一步都先贡献历史次数再加当前前缀，不能把空区间加入。

3. 最长连续序列外层遍历原数组，会怎样退化？

输入包含大量1及2..m时，每个1都没有前驱0，会重复扩展整段。外层遍历去重集合才能保证每个连续块只启动一次；仅仅给查询套上哈希表并不能保证线性。

4. 两个不同的异位词频次键能有相同哈希吗？

可以，哈希冲突本来就允许。容器会继续用完整array比较相等性，因此不会合并。若只把哈希摘要作为键并丢弃原频次信息，才无法区分碰撞。

5. 数字0能作为两个单次数字之一吗？

可以，只要另一个数字与0不同，全部异或仍非0，可以找到一个区分位。异或结果为0表示不满足两个不同单次数字加成对其余数字的契约，而不是简单说明其中存在0。

6. mask=1010的子掩码有哪些？

按(sub-1)&mask递减枚举为1010、1000、0010、0000，共4个。它有两个置1位，所以子集数为2²；处理0后必须退出，不能再更新回mask。

7. [1,1]按位枚举有几个下标子集、几个不同值子集？

下标子集有4个：空、选第一个、选第二个、全选；不同的值列表只有3种：[]、[1]、[1,1]。位模式保证下标集合唯一，不保证值列表去重。

8. 面试讲哈希O(n)和位运算O(1)时应补哪些限定？

哈希O(n)通常是平均复杂度，需考虑键处理成本及最坏冲突；位运算常数时间是固定宽度整数下的模型，枚举2^n个掩码仍是指数。还应说明数值范围、移位范围、输出大小及题目给定的出现次数前提。
