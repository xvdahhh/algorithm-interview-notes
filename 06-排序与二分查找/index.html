06.01

归并排序、稳定性与逆序对

知识与适用场景

归并先递归排序两半，再用双指针合并。相等时优先取左半元素可以保持稳定性，即原本相等元素的相对顺序不变。稳定性对多字段排序有意义。

1.1 排序比较表中的前提不能省略

比较排序在一般输入上需要区分n!种排列，决策树高度至少log₂(n!)=Ω(nlogn)。这不是说所有排序都必须nlogn：计数排序利用有限整数值域，突破的是比较模型前提，而不是信息论结论。

稳定是指键相等的记录保持原始相对顺序，不是说算法每次运行结果一样。只排int时肉眼不易看出区别；把元素表示为(分数,姓名)或(键,原始编号)就能观察。

1.3 归并正确性：递归保证两半有序，合并只选最小未消费项

使用半开区间[l,r)，长度不超过1时天然有序。递归得到[l,m)、[m,r)有序后，比较两侧首个未使用元素；更小者就是所有未使用元素的最小者。循环不断扩展一个有序输出前缀，直到两边耗尽。

相等时先拿左边可保持稳定：左区间的记录原本就先于右区间，同一区间内部顺序又由递归保持。每层合并总长度O(n)，树高O(logn)；只分配一次tmp并复用，避免每层反复创建大量临时数组。

    int id; // original identity, not part of the sorting key
};
void stableMergeRange(vector<Record>& a, vector<Record>& tmp, int l, int r) {
    if (r - l <= 1) return;
    int m = l + (r - l) / 2;
    stableMergeRange(a, tmp, l, m);
    stableMergeRange(a, tmp, m, r);
    int i = l, j = m, out = l;
    while (i < m && j < r)
        tmp[out++] = a[i].key <= a[j].key ? a[i++] : a[j++];
    while (i < m) tmp[out++] = a[i++];
    while (j < r) tmp[out++] = a[j++];
    for (int k = l; k < r; ++k) a[k] = tmp[k];
}
void stableMergeSort(vector<Record>& a) {
    vector<Record> tmp(a.size());
    stableMergeRange(a, tmp, 0, (int)a.size());
}

1.5 逆序对：为什么一次加左半剩余长度

逆序对要求原下标i<j且a[i]>a[j]。递归分别统计左右内部的逆序对；合并时，若右值a[j]小于左边当前a[i]，由于左半有序，a[i..m)的每个值都大于它，增加m-i。每个跨区间逆序对在选取其右端点时恰好计一次。

相等不构成逆序对，所以合并条件仍用<=优先取左侧。[2,2]应计0；长度n严格逆序最多n(n-1)/2，计数用long long。该实现会顺带将输入排序，若要保留原数组请先复制。

long long inversionRange(vector<int>& a, vector<int>& tmp, int l, int r) {
    if (r - l <= 1) return 0;
    int m = l + (r - l) / 2;
    long long answer = inversionRange(a, tmp, l, m);
    answer += inversionRange(a, tmp, m, r);
    int i = l, j = m, out = l;
    while (i < m && j < r) {
        if (a[i] <= a[j]) tmp[out++] = a[i++];
        else { answer += m - i; tmp[out++] = a[j++]; }
    }
    while (i < m) tmp[out++] = a[i++];
    while (j < r) tmp[out++] = a[j++];
    for (int k = l; k < r; ++k) a[k] = tmp[k];
    return answer;
}

1.8 比较器必须是严格弱序，不能写<=

comp(x,x)必须为false；比较关系还需要传递，且由“互不小于”定义的等价关系也要传递。使用<=会让元素小于自身，违反标准算法要求，可能触发未定义行为，而不只是得到某种不稳定结果。

多字段排序可写：先比较score，score相同再比较id；或用tie(a.score,a.id)<tie(b.score,b.id)。不要用a.score-b.score<0，减法可能溢出。普通浮点<遇到NaN时也不满足所有输入上的严格弱序，应拒绝NaN或设计明确的全序规则。

std::stable_sort保证稳定，但C++17中的复杂度与可用额外内存相关：内存足够时O(nlogn)比较，否则可到O(nlog²n)。不要把std::sort实现细节和自己写的普通快排混为一谈。

1.9 堆排序：迭代下沉与自底向上建堆

维护最大堆，堆顶与未排序区末尾交换后，末尾就是本轮最大值，不再参与下沉。建堆从最后一个非叶节点开始；总成本是Σ(高度h的节点数·h)=O(n)，不是每个节点都下沉logn层。随后n次取顶总O(nlogn)，辅助空间O(1)，不稳定。

void siftDown(vector<int>& a, int root, int size) {
    while (root < size / 2) {
        int child = root * 2 + 1;
        if (child + 1 < size && a[child] < a[child + 1]) ++child;
        if (a[root] >= a[child]) break;
        swap(a[root], a[child]);
        root = child;
    }
}
void heapSort(vector<int>& a) {
    int n = (int)a.size();
    for (int root = n / 2 - 1; root >= 0; --root) siftDown(a, root, n);
    for (int end = n - 1; end > 0; --end) {
        swap(a[0], a[end]);
        siftDown(a, 0, end);
    }
}

1.10 稳定计数排序：累计末位置，逆向填入

end[v]起初是键<=v的元素总数，也就是该键最后一个位置的后一位；逆向扫描并递减填入，使较晚的相等记录落在较后的位置，保持稳定。时间O(n+K)，含输出的空间O(n+K)。若只按频次重建整数数列，可只用O(K)额外计数，但那无法表达记录的稳定顺序。

struct CountItem { int key; int id; };
vector<CountItem> stableCountingSort(const vector<CountItem>& a, int keyCount) {
    if (keyCount <= 0 || keyCount > 1000000)
        throw invalid_argument("require 1 <= keyCount <= 1000000");
    vector<size_t> end(keyCount, 0);
    for (const auto& item : a) {
        if (item.key < 0 || item.key >= keyCount)
            throw invalid_argument("key outside [0, keyCount)");
        ++end[item.key];
    }
    for (int key = 1; key < keyCount; ++key) end[key] += end[key - 1];
    vector<CountItem> answer(a.size());
    for (size_t i = a.size(); i > 0; --i) {
        const auto& item = a[i - 1];
        answer[--end[item.key]] = item;
    }
    return answer;
}

面试追问：关键点完整解答

把归并中的<=改成<会改变什么？

数值排序仍然正确，但相等时会优先选右半元素。左半同键记录原本位于右半之前，这样会颠倒它们的相对顺序，失去稳定性。

逆序对为什么加m-i而不是1？

右值小于左半当前最小未消费值，所以也小于左半所有后续值。对应原下标都在左半，满足下标较小，故这m-i个元素各贡献一对。

比较器<=为什么不是一种合法的稳定排序办法？

稳定性由算法如何处理相等项决定，而<=违反严格弱序的自反排除要求comp(x,x)=false。标准排序依赖该要求，违规不能保证算法正确甚至不能保证正常结束。

为什么建堆O(n)，但反复插入建堆通常O(nlogn)？

自底向上下沉时，大部分节点靠近叶子，下沉高度很小；按高度汇总是线性。逐个插入会执行向上调整，每次最多logn，得到O(nlogn)上界，两种建堆过程不同。

计数排序O(n+K)能无条件替代比较排序吗？

不能。它要求可映射到较小离散值域，K太大会耗费大量初始化时间和内存；任意字符串或复杂比较关系不能直接当数组下标。稳定记录版本还需要O(n)输出缓存。

稳定排序与多字段排序有什么关系？

可先按次关键字排序，再用稳定排序按主关键字排序，保持同主键记录的次关键字顺序。也可一次用严格弱序的多字段比较器；这时稳定性只影响所有比较字段都相等的记录。

06.02

快速排序与三路分区

知识与适用场景

快排通过分区把较小值放左边、较大值放右边，再递归处理。平均 O(n log n)，选择极差基准时最坏 O(n²)。大量重复值时，三路分区能一次跳过整个相等区域。

2.1 三路分区：一边分类，一边缩短未知区

闭区间[l,r]中维护四段：[l,lt)小于pivot，[lt,i)等于pivot，[i,gt]未知，(gt,r]大于pivot。初始lt=i=l、gt=r，三个已知区为空。每次处理a[i]，未知区长度必须减少1。

小于pivot：与lt交换，然后lt和i同时增加；大于pivot：与gt交换，仅gt减少，因为换到i的值尚未分类；等于pivot：只增加i。结束时i=gt+1，未知区空，只需排序两侧，整个相等区无需再递归。pivot必须保存值的副本，不要用会被交换的数组元素引用。

2.3 随机基准与递归栈是两个不同问题

基础代码取中间位置的值，不等于取数值中位数，特殊输入仍可导致极不均衡分区。随机取基准能对固定输入给出期望O(nlogn)，但最坏时间仍是O(n²)。全相等输入用三路分区一轮即可结束，时间O(n)。

防栈溢出的另一个技巧：只递归较短的一侧，把较长的一侧放在while循环继续处理。每次真正深入递归的子问题至多原来一半，所以栈深最坏O(logn)，即使分区很差，时间仍可能二次。空间优化不等于消除了时间最坏情况。

2.4 随机三路快排：短边递归、长边迭代

void randomQuickRange(vector<int>& a, int l, int r, mt19937& rng) {
    while (l < r) {
        uniform_int_distribution<int> pick(l, r);
        int pivot = a[pick(rng)];
        int lt = l, i = l, gt = r;
        while (i <= gt) {
            if (a[i] < pivot) swap(a[lt++], a[i++]);
            else if (a[i] > pivot) swap(a[i], a[gt--]);
            else ++i;
        }
        if (lt - l < r - gt) {
            randomQuickRange(a, l, lt - 1, rng);
            l = gt + 1;
        } else {
            randomQuickRange(a, gt + 1, r, rng);
            r = lt - 1;
        }
    }
}
void randomizedQuickSort(vector<int>& a, uint32_t seed) {
    mt19937 rng(seed);
    if (!a.empty()) randomQuickRange(a, 0, (int)a.size() - 1, rng);
}

void quickSort(vector<int>& a, int l, int r) {
    if (l >= r) return;
    int pivot = a[l + (r-l)/2];
    int lt=l, i=l, gt=r;
    while (i <= gt) {
        if (a[i] < pivot) swap(a[lt++], a[i++]);
        else if (a[i] > pivot) swap(a[i], a[gt--]);
        else ++i;
    }
    quickSort(a, l, lt-1);
    quickSort(a, gt+1, r);
}
void sortArray(vector<int>& a) {
    if (!a.empty()) quickSort(a, 0, (int)a.size()-1);
}

快排不是稳定排序。需要可靠最坏性能时通常使用标准库 sort，或自己实现内省排序；随机化只能降低遇到极端分区的概率。

2.5 第K小：排序两侧是多余工作

将K定义为1开始编号，目标下标target=K-1。分区后，[l,lt)的秩都更小，[lt,gt]都是pivot，[gt+1,r]都更大；若target落在相等区直接返回，否则只缩小到包含target的一边。

随机基准下，常数概率产生足够均衡的分区，期望剩余规模按常数比例下降，总扫描量为O(n)，不是每轮都花n再做logn轮。最坏持续只减少一个元素时仍为O(n²)。第K大可转成第n-K+1小，但先检查K合法。

2.6 迭代快速选择：仅求第K小

int kthSmallest(vector<int>& a, int k, uint32_t seed) {
    int n = (int)a.size();
    if (k < 1 || k > n) throw out_of_range("k outside [1,n]");
    int target = k - 1, l = 0, r = n - 1;
    mt19937 rng(seed);
    while (l <= r) {
        uniform_int_distribution<int> pick(l, r);
        int pivot = a[pick(rng)];
        int lt = l, i = l, gt = r;
        while (i <= gt) {
            if (a[i] < pivot) swap(a[lt++], a[i++]);
            else if (a[i] > pivot) swap(a[i], a[gt--]);
            else ++i;
        }
        if (target < lt) r = lt - 1;
        else if (target > gt) l = gt + 1;
        else return pivot;
    }
    throw logic_error("unreachable for valid input");
}

面试追问：关键点完整解答

为什么大于pivot时交换完不能++i？

右侧gt指向未知区，换回来的值还没有被检查。若直接跳过，可能把一个应去左侧的小值遗留在相等区。每轮只保证右边界缩小，而不是i也可以推进。

为什么pivot要保存成int值而非引用？

数组分区会交换元素。若pivot引用某个位置，该位置的值可能被换走，比较基准在中途改变，已经建立的四段不变量就失效。

中间位置作基准为什么不保证平衡？

位置的中间不代表值的中位数。该位置可能恰好是最小或最大值，构造输入也可让后续每轮继续如此。随机基准改善期望行为，不能给出最坏nlogn保证。

短边递归如何把最坏栈深降到logn？

相等区之外的两侧总长度小于当前长度，较短侧长度至多一半。只有这侧会新增调用栈层；较长侧在当前栈帧中循环处理，因此每深入一层规模至少减半。

快速选择遇到大量重复值是否还要逐个定位？

三路分区会给出整个等于pivot的秩区间。目标下标落在里面时答案就是pivot，无须区分某个相等元素的身份；若题目要按附加字段区分，则比较键必须包含该字段。

第K大为什么是下标n-K，而不是K-1？

升序排序后最大元素位于n-1，第二大位于n-2，所以第K大位于n-K。对应1开始的第n-K+1小。K不合法时必须先拒绝，不能让越界算术进入选择过程。

知识与适用场景

lower_bound 返回第一个 >=x 的位置，upper_bound 返回第一个 >x 的位置。两者之差就是 x 的出现次数；找不到时可能返回 end。

3.1 找边界前，先把命题写成false→true

在升序数组中，P(i):a[i]>=x 从false变成true；lower_bound寻找第一个true。维护[0,l)全部false，[r,n)全部true，[l,r)尚未确定。r=n时右侧已知true区域为空，n作为“没有true”的返回哨兵，不需要读取a[n]。

若a[mid]>=x，mid和之后都可归入true区域，令r=mid，不能mid-1，因为mid自身可能就是第一个true。否则mid及之前都false，令l=mid+1。终止l=r时未知区为空，该位置恰好是分界。

注意：待检查元素区间是[l,r)，但最终边界位置可能等于r。不要将“元素候选范围”与“边界答案的位置范围”混为一谈；例如全false时返回n。

int lowerBoundIndex(const vector<int>& a, int x) {

3.5 标准库的比较器和迭代器要求

lower_bound要求范围对给定比较谓词分区；升序有序是对所有查询都能满足该要求的常用前提。若数组按降序排序，二分也必须采用一致的比较规则。不要在未排序数组上调用后碰巧得到一个下标，就以为算法有效。

vector是随机访问迭代器，二分比较和移动都为O(logn)。list或set的通用lower_bound虽然比较次数O(logn)，迭代器前进总量可能O(n)；set/map应优先用成员lower_bound，利用树结构做到O(logn)。

pair<int,int> searchRange(const vector<int>& a, int x) {
    auto first = lower_bound(a.begin(), a.end(), x);
    if (first == a.end() || *first != x) return {-1,-1};
    auto after = upper_bound(first, a.end(), x);
    return {(int)(first-a.begin()), (int)(after-a.begin())-1};

3.6 旋转数组：不是整体有序，但至少一半有序

无重复的升序数组旋转后，比较a[l]与a[mid]：若a[l]<=a[mid]，左半[l,mid]有序；判断目标是否在[a[l],a[mid])即可决定去向。否则右半[mid,r]有序，判断目标是否在(a[mid],a[r]]。先单独检查a[mid]==target，再排除mid。

存在重复时，a[l]==a[mid]==a[r]无法判断断点在哪边。已知mid不是目标后，只能安全缩去两端相等值，可能退化成逐个排除；例如大量1中夹一个0。不能同时声称支持任意重复又保证最坏O(logn)。

3.7 旋转数组搜索：无重复与允许重复的两个接口

int searchRotatedDistinct(const vector<int>& a, int target) {
    int l = 0, r = (int)a.size() - 1;
    while (l <= r) {
        int mid = l + (r - l) / 2;
        if (a[mid] == target) return mid;
        if (a[l] <= a[mid]) {
            if (a[l] <= target && target < a[mid]) r = mid - 1;
            else l = mid + 1;
        } else {
            if (a[mid] < target && target <= a[r]) l = mid + 1;
            else r = mid - 1;
        }
    }
    return -1;
}
bool searchRotatedWithDuplicates(const vector<int>& a, int target) {
    int l = 0, r = (int)a.size() - 1;
    while (l <= r) {
        int mid = l + (r - l) / 2;
        if (a[mid] == target) return true;
        if (a[l] == a[mid] && a[mid] == a[r]) { ++l; --r; continue; }
        if (a[l] <= a[mid]) {
            if (a[l] <= target && target < a[mid]) r = mid - 1;
            else l = mid + 1;
        } else {
            if (a[mid] < target && target <= a[r]) l = mid + 1;
            else r = mid - 1;
        }
    }
    return false;
}

3.9 峰值二分：保留的是“某个峰”，不是某个固定答案

前提a相邻元素不相等，数组两端之外视为负无穷。若a[mid]<a[mid+1]，沿上坡向右走：要么某处转为下降形成峰，要么一直上升到右端，右端本身就是峰；因此右侧必存在峰。反方向同理。

数组可以有多个峰，不要求全局先增后减。这里的“上坡”布尔值并不在整个数组上单调，因此不能照搬“第一个true”的证明；正确依据是每次保留的区间仍包含一个峰以及边界斜率条件。

3.11 两个有序数组中位数：二分分割线，而不是枚举数值

在较短数组A上选择左边拿i个，另一个数组B拿j=(m+n+1)/2-i个，让总左侧比右侧最多多一个。只要A左最大<=B右最小且B左最大<=A右最小，所有左侧元素就不大于右侧；奇数总长度取左最大，偶数取左右边界均值。

若A左最大>B右最小，说明A左侧取多了，i减小；若B左最大>A右最小，说明A左侧取少了，i增大。在较短数组上二分可使j始终落在合法范围，边界为空时用长整型极值作哨兵。

面试追问：关键点完整解答

二分模板用r=mid，为什么不会死循环？

当l<r时下取整mid<r，所以r=mid严格减小右边界；另一支l=mid+1严格增大左边界。关键是每个分支都减少r-l，而不是看到mid就随意加减1。

找不到目标时lower_bound返回n还是-1？

它返回插入边界，范围为[0,n]，可能在数组内部指向更大值，也可能等于n。判断存在必须同时检查p<n和a[p]==target；-1只是某些封装接口约定，不是lower_bound的语义。

最后一个<=x为什么用upper_bound减1？

upper_bound恰是第一个>x的位置，之前的最后一个元素就是最后一个<=x。若upper_bound位置为0，说明不存在符合项，返回有符号下标-1，不能对begin迭代器直接做非法前移。

旋转数组有重复时，为什么最坏只能线性？

大量相等值会隐藏断点位置，例如只有一个0而其他全为1。端点与中点相等时无法据此排除半边，只能逐步缩小。O(logn)保证依赖能确定哪半有序的额外信息。

峰值二分需要数组整体单峰吗？

不需要，但要求相邻不等且边界外为负无穷。比较中点斜率能证明某一侧必有一个峰，从而安全保留它；并不是在整个数组上寻找一个单调布尔谓词的边界。

中位数为什么在较短数组上二分分割？

这样i从0到m时，按左侧总数计算出的j自然在0..n范围内，搜索空间也更小。若在长数组上随意取i，j可能为负或超过短数组长度，还需额外限制i的上下界。

答案二分：最小运输能力

知识与适用场景

答案二分要求可行性单调。运输容量越大，需要的天数越少，因此存在“不可行→可行”的分界。对每个候选容量，按顺序尽量装满当前天即可检查可行性。

4.1 答案二分的四个证明义务

第一，真实答案处于初始范围；第二，check(cap)确实等价于该容量可行，而不是一种不完整的尝试；第三，可行性具有单调性；第四，每轮保留答案并严格缩小范围。只看见“最小化最大值”不足以推出二分代码正确。

基础运力题规定货物顺序不变，每天装运一个连续前缀，重量为正。约定n<=100000、每件重量<=10^9、非空输入days>=1；这样总重和load+x都可用long long表示。空数组直接返回0，即使days<=0也不进入非空参数校验，这是基础接口的约定。

4.2 为什么运力判定可以每天尽量装满

固定容量cap，每天贪心装到再加一件就超容量。用归纳比较任何合法方案：第一天贪心能完成的前缀不短于它；若前t天贪心已经完成至少同样多货物，第t+1天也可从更靠后位置出发，正重量保证它不会比另一方案覆盖更少的前缀。因此贪心所需天数最少。

容量增大时，原来可行的装法仍可行，所以check从false变true。下界max(w)排除装不下单件的容量，上界sum(w)可在一天装完，必可行。每次check O(n)，二分次数O(log(S-M+1))；计入至少一次读入的统一写法为O(n·(1+log(S-M+1)))。

4.5 把运力题变成分割数组：前提差一点，证明就变了

非负数组分成至多D个连续非空段、最小化最大段和，与运力模型相同。若要求恰好D段且1<=D<=n，非负数下可把不足D段的方案继续拆开而不增加最大段和，因此可复用判定。

long long shipCapacity(const vector<int>& w, int days) {
    if (w.empty()) return 0;
    if (days <= 0) throw invalid_argument("days must be positive");
    long long lo = *max_element(w.begin(),w.end());
    long long hi = accumulate(w.begin(),w.end(),0LL);
    auto ok = [&](long long cap) {
        int used=1;
        long long load=0;
        for (int x:w) {
            if (load+x>cap) { ++used; load=0; }
            load+=x;
        }
        return used<=days;
    };
    while (lo<hi) {
        long long mid=lo+(hi-lo)/2;
        if (ok(mid)) hi=mid;
        else lo=mid+1;
    }
    return lo;
}

int minimumEatingSpeed(const vector<int>& piles, long long hours) {
    if (piles.empty()) return 0;
    if (hours <= 0) throw invalid_argument("hours must be positive");
    int hi = 0;
    for (int value : piles) {
        if (value <= 0) throw invalid_argument("piles must be positive");
        hi = max(hi, value);
    }
    if (hours < (long long)piles.size()) return -1;
    auto feasible = [&](int speed) {
        long long used = 0;
        for (int value : piles) {
            used += value / speed + (value % speed != 0);
            if (used > hours) return false;
        }
        return true;
    };
    int lo = 1;
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (feasible(mid)) hi = mid;
        else lo = mid + 1;
    }
    return lo;
}

4.7 最大化最小距离：最后一个可行答案

从最左位置开始，每次选择距离满足要求的最早位置。它为后续放置保留最多空间，可用交换论证把任意可行方案的当前点左移到贪心点而不损害未来，因此判定完备。距离变大只会更难，可行性true→false。

位置是int，差值先转long long，覆盖INT_MIN到INT_MAX。重复坐标按不同可选位置处理，因此距离0也可能是答案；若题目要求物理位置唯一，应先明确输入约定。接口复制并排序，不改调用者输入。总时间O(nlogn+n·log(R+1))、复制空间O(n)，R为坐标跨度；上取整mid在本例范围内不会溢出。

long long maximumMinimumDistance(vector<int> positions, int count) {
    int n = (int)positions.size();
    if (count < 2 || count > n) throw invalid_argument("require 2 <= count <= n");
    sort(positions.begin(), positions.end());
    auto feasible = [&](long long distance) {
        int placed = 1;
        long long last = positions[0];
        for (int i = 1; i < n; ++i) {
            if ((long long)positions[i] - last >= distance) {
                last = positions[i];
                if (++placed == count) return true;
            }
        }
        return false;
    };
    long long lo = 0, hi = (long long)positions.back() - positions.front();
    while (lo < hi) {
        long long mid = lo + (hi - lo + 1) / 2;
        if (feasible(mid)) lo = mid;
        else hi = mid - 1;
    }
    return lo;
}

4.8 最后一个true为什么用上取整mid

若lo=4、hi=5，下取整mid=4，而可行分支更新lo=mid会使区间完全不变，造成死循环。上取整得到5，无论可行还是不可行，区间都会变成一个点。另一种合法做法是改用不变量不同的哨兵区间，但不能只替换mid而不检查全部边界语义。

lo+(hi-lo)/2的防溢出也有前提：hi-lo本身必须可表示。本章数组下标非负，资源区间与坐标跨度都已限制，因此满足。若二分完整有符号64位范围，差值也可能溢出，需要单独设计中点计算。

4.9 整数平方根：用除法比较避免mid*mid溢出

返回最大的非负整数r，使r²<=x。uint64_t最大输入的平方根不超过2^32-1，所以hi的界正确；循环中mid>=1，不会除零。用mid<=x/mid代替乘法比较，避免中间乘积溢出。固定64位至多32轮，空间O(1)。

uint64_t floorSquareRoot(uint64_t x) {
    uint64_t lo = 0, hi = min(x, uint64_t{UINT32_MAX});
    while (lo < hi) {
        uint64_t mid = lo + (hi - lo + 1) / 2;
        if (mid <= x / mid) lo = mid;
        else hi = mid - 1;
    }
    return lo;
}

4.10 实数二分与边界自检

若答案是实数，不能用lo=mid+1。可固定迭代次数，或在hi-lo<=eps时停止；要考虑浮点舍入使mid等于端点，以及误差是绝对还是相对。把整数模板里的+1删除并不自动完成数值分析。

输出最小可行值ans后，可检查check(ans)为真，且ans大于域下界时check(ans-1)为假；输出最大可行值时检查check(ans)为真，且域内ans+1不可行。这种邻接验证很适合发现边界偏一。

面试追问：关键点完整解答

看到“最小化最大值”就能直接答案二分吗？

还需给出答案范围、可行性的单调性和一个正确且足够快的判定算法。单调性成立不代表容易判定，例如允许重排后的装箱问题就不能直接用原顺序贪心。

运力上界为什么用总重而不是平均重量？

总重一定可以在一天装完，是可靠的可行上界；平均重量只是可能的下界信息，不能保证装下最大单件，也可能受连续分组约束影响。二分需要一个已知可行的端点。

运力题每天尽量装满为什么不会损害后面？

在容量固定且重量为正的顺序模型里，装得更多只会把剩余任务变成更短的后缀。通过已完成前缀的归纳，贪心每一天都不会比其他方案完成得少，所以其天数最少。

为什么香蕉时间不能用总量除以速度向上取整？

每小时不能跨堆，余下时间不能拿去吃另一堆。例如[1,1]、速度2仍需2小时，而ceil(2/2)=1会错误合并时间。必须逐堆取整后求和。

最大化最小距离为什么可行时更新lo而不是hi？

要找最大的true。mid可行说明所有更小距离也可行，可以把lo推进到mid，但仍需探索更大值；不可行则排除mid及更大值，hi=mid-1。配合上取整mid保证进展。

平方根二分为什么不用mid*mid<=x？

乘法可能先溢出，再与x比较就失去意义。mid>0时不等式等价于mid<=x/mid，采用整数除法仍能准确判定；本例用上取整且只在lo<hi时循环，确保mid不为0。

void siftDown(vector<int>& a, int root, int size) {
    while (root < size / 2) {
        int child = root * 2 + 1;
        if (child + 1 < size && a[child] < a[child + 1]) ++child;
        if (a[root] >= a[child]) break;
        swap(a[root], a[child]);
        root = child;
    }
}
void heapSort(vector<int>& a) {
    int n = (int)a.size();
    for (int root = n / 2 - 1; root >= 0; --root) siftDown(a, root, n);
    for (int end = n - 1; end > 0; --end) {
        swap(a[0], a[end]);
        siftDown(a, 0, end);
    }
}

        int i = l + (r - l) / 2, j = half - i;
        long long al = i == 0 ? LLONG_MIN : a[i - 1];
        long long ar = i == m ? LLONG_MAX : a[i];
        long long bl = j == 0 ? LLONG_MIN : b[j - 1];
        long long br = j == n ? LLONG_MAX : b[j];
        if (al <= br && bl <= ar) {
            if (((long long)m + n) % 2 != 0) return (double)max(al, bl);
            return (max(al, bl) + min(ar, br)) / 2.0;
        }
        if (al > br) r = i - 1;
        else l = i + 1;
    }
    throw invalid_argument("sorted input required");
}

int minimumEatingSpeed(const vector<int>& piles, long long hours) {
    if (piles.empty()) return 0;
    if (hours <= 0) throw invalid_argument("hours must be positive");
    int hi = 0;
    for (int value : piles) {
        if (value <= 0) throw invalid_argument("piles must be positive");
        hi = max(hi, value);
    }
    if (hours < (long long)piles.size()) return -1;
    auto feasible = [&](int speed) {
        long long used = 0;
        for (int value : piles) {
            used += value / speed + (value % speed != 0);
            if (used > hours) return false;
        }
        return true;
    };
    int lo = 1;
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (feasible(mid)) hi = mid;
        else lo = mid + 1;
    }
    return lo;
}

long long maximumMinimumDistance(vector<int> positions, int count) {
    int n = (int)positions.size();
    if (count < 2 || count > n) throw invalid_argument("require 2 <= count <= n");
    sort(positions.begin(), positions.end());
    auto feasible = [&](long long distance) {
        int placed = 1;
        long long last = positions[0];
        for (int i = 1; i < n; ++i) {
            if ((long long)positions[i] - last >= distance) {
                last = positions[i];
                if (++placed == count) return true;
            }
        }
        return false;
    };
    long long lo = 0, hi = (long long)positions.back() - positions.front();
    while (lo < hi) {
        long long mid = lo + (hi - lo + 1) / 2;
        if (feasible(mid)) lo = mid;
        else hi = mid - 1;
    }
    return lo;
}

uint64_t floorSquareRoot(uint64_t x) {
    uint64_t lo = 0, hi = min(x, uint64_t{UINT32_MAX});
    while (lo < hi) {
        uint64_t mid = lo + (hi - lo + 1) / 2;
        if (mid <= x / mid) lo = mid;
        else hi = mid - 1;
    }
    return lo;
}

long long bruteInversions(const vector<int>& a) {
    long long answer = 0;
    for (int i = 0; i < (int)a.size(); ++i)
        for (int j = i + 1; j < (int)a.size(); ++j)
            answer += a[i] > a[j];
    return answer;
}
int bruteSpeed(const vector<int>& piles, long long hours) {
    if (piles.empty()) return 0;
    if (hours < (long long)piles.size()) return -1;
    int maximum = *max_element(piles.begin(), piles.end());
    for (int speed = 1; speed <= maximum; ++speed) {
        long long used = 0;
        for (int value : piles) used += (value + speed - 1) / speed;
        if (used <= hours) return speed;
    }
    return -1;
}
long long bruteDistance(vector<int> positions, int count) {
    sort(positions.begin(), positions.end());
    int n = (int)positions.size();
    long long best = 0;
    for (unsigned mask = 0; mask < (1U << n); ++mask) {
        int selected = 0;
        for (unsigned bits = mask; bits != 0; bits &= bits - 1) ++selected;
        if (selected != count) continue;
        long long distance = LLONG_MAX;
        int previous = -1;
        for (int i = 0; i < n; ++i) {
            if ((mask & (1U << i)) == 0) continue;
            if (previous != -1)
                distance = min(distance, (long long)positions[i] - positions[previous]);
            previous = i;
        }
        best = max(best, distance);
    }
    return best;
}

章末自测：八个关键问题及答案

1. [2A,1B,2C,1D]稳定排序后是什么？

按数字键排序应为[1B,1D,2A,2C]。相等键的原顺序不变；若归并相等时优先右侧，就可能颠倒B/D或A/C。

2. 左半[2,4]、右半[1,3]合并时有几个跨区逆序对？

取右值1时与2、4产生两对；取右值3时与剩余4产生一对，共三对。左右内部若还有逆序对，则由递归部分另外统计。

3. 快排遇到大于pivot的值，换到右端后i为什么不变？

换回来的值属于未知区，可能小于、等于或大于pivot，必须重新分类。只减少gt就已保证未知区变短，不需要为了“推进循环”而错误跳过它。

4. [1,2,2,2,4]中2的左右闭区间是多少？

lower_bound为1，upper_bound为4，出现范围[1,3]，数量3。upper_bound本身是最后一个匹配位置的后一位，不是最后匹配位置。

5. lo=4、hi=5，求最大可行值时下取整有什么问题？

若mid=4可行而更新lo=mid，区间原地不动。上取整mid=5会使lo升到5或hi降到4，保证终止。

6. 旋转数组搜索、峰值搜索都需要全局单调谓词吗？

不需要。旋转搜索利用一半有序的结构，峰值搜索利用上坡方向存在峰的证明。它们每轮仍可安全排除一半，但不能用不存在的全局false→true性质解释。

7. 运力允许重排时，原贪心为什么可能错误？

[2,2,3,3]容量5，按原顺序贪心为[2,2]、[3]、[3]需要3天，但重排后[2,3]、[2,3]只需2天。原判定会把实际可行容量误判为不可行。

8. 如何检验一个答案二分结果是否偏一？

最小可行答案ans应满足check(ans)=true，且域内ans-1为false；最大可行则检查ans+1为false。另测上下界重合、答案等于某个端点、只有两个候选值和全部可行/不可行的接口处理。
