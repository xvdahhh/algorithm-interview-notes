15.01

一场 40 分钟手撕的节奏

知识与适用场景

前 3 分钟确认题意和样例；接着约 7 分钟从暴力推到优化并说清不变量；约 20 分钟完成代码；剩余时间用于测试、复杂度和追问。时间仅作为训练参照，应随题目难度调整。

15.1.1 先把题意翻译成函数契约

按影响算法选择的顺序提问：输入是否有序、数据量多大、值是否可负、能否修改输入、返回下标还是值、要任意解还是全部解。再问边界：空输入是否合法、没有答案怎样返回、多个答案是否有优先级、下标从 0 还是 1 开始。不要机械地问与当前题无关的问题。

例如“两数之和”至少有三种不同任务：有序数组返回任意位置对、无序数组返回原位置对、返回全部不同值对。第一种可用相向双指针；第二种常用哈希；第三种要规定去重，答案量也要计入成本。若要求全部位置对，n 个相同数字就可能产生 n(n−1)/2 个结果。

15.1.3 可复用的口述示范：不是逐字符读代码

开场：“我确认一下，数组已按非降序排列，返回两个不同位置的 0 下标，任意一组即可，无解返回 {-1,-1}，且不能修改输入，对吗？”题设已明确的部分直接复述，不必重复索要确认。

推导：“枚举所有下标对是 O(n²)。排序给了单调性：如果 a[l]+a[r] 小于目标，那么固定 l，任何不超过 r 的右端都不能补足目标，因此可以丢弃 l。大于目标时同理丢弃 r。未被排除的答案始终位于 [l,r]，所以不会漏解。”

编码时只同步关键决策：“l<r 保证不重复用同一位置；先转成 long long 再相加；失败路径统一返回约定的哨兵。”结束时用 [1,2,4,8]、目标 6 手推：9 太大删右，5 太小删左，6 命中。最后报 O(n) 时间、O(1) 额外空间。

推导 / 不变量

以有序数组两数之和为例：先确认是否返回原下标、是否存在解、是否允许同一元素使用两次，然后解释相向双指针的排除依据，再编码。

手推一个例子

口述示例：数组已排序。若两端之和偏小，固定左端并减小右端只会更小，所以当前左端不可能参与答案，可以安全丢弃。

C++17
下载 .cpp
pair<int,int> twoSumSorted(const vector<int>& a,long long target){
    int l=0,r=(int)a.size()-1;
    while(l<r){
        long long sum=(long long)a[l]+a[r];
        if(sum==target) return {l,r};
        if(sum<target) ++l;
        else --r;
    }
    return {-1,-1};
}
复杂度
时间 O(n)，空间 O(1)，输入为非降序；返回 0 下标，无解返回 {-1,-1}。
易错点与边界
不要在代码写完后才发现题目要求 1 下标或多个解。卡住时说明已验证的性质和具体障碍，而不是无声地重复试代码。

15.1.5 无序两数之和：查找必须在插入之前

返回 optional 避免把合法下标与失败混淆。先查询再插入保证两个位置不同；try_emplace 保留每个值第一次出现的位置，但整体仅承诺任意解，不承诺全局字典序最小。先判断目标能否由两个 int 相加得到，避免极端 long long 目标在求补数时溢出。哈希平均 O(n)、最坏 O(n²)，额外空间 O(n)。

optional<pair<size_t,size_t>> twoSumOriginal(const vector<int>& a, long long target) {
    if (target < 2LL * INT_MIN || target > 2LL * INT_MAX) return nullopt;
    unordered_map<long long,size_t> seen;
    for (size_t i = 0; i < a.size(); ++i) {
        const long long need = target - static_cast<long long>(a[i]);
        auto it = seen.find(need);
        if (it != seen.end()) return pair<size_t,size_t>{it->second, i};
        seen.try_emplace(a[i], i);
    }
    return nullopt;
}

15.1.6 全部不同值对：重复值与重复位置不是一回事

参数按值接收，明确付出 O(n) 拷贝以保护调用者输入。例 [1,1,2,2,3,3]、目标 4 返回 (1,3)、(2,2)；(2,2) 需要确实存在两个 2。命中后同时跳过两端相同值，只消除重复值对。总时间 O(n log n)，包含输入副本与结果的空间 O(n+k)。

vector<pair<int,int>> uniqueValuePairs(vector<int> a, long long target) {
    vector<pair<int,int>> result;
    if (a.size() < 2) return result;
    sort(a.begin(), a.end());
    size_t l = 0, r = a.size() - 1;
    while (l < r) {
        long long sum = static_cast<long long>(a[l]) + a[r];
        if (sum < target) ++l;
        else if (sum > target) --r;
        else {
            const int left = a[l], right = a[r];
            result.emplace_back(left, right);
            while (l < r && a[l] == left) ++l;
            while (l < r && a[r] == right) --r;
        }
    }
    return result;
}

经典考点与练习

训练：录音完成一次从澄清到复杂度的 5 分钟口述；检查是否明确了排序、重复值和下标约定。

面试追问：关键点完整解答

1. 一上来知道最优解，还要完整写一遍暴力吗？

不必把暴力代码也写完。用一句话交代可行基线、复杂度和瓶颈，再解释如何消除重复工作即可。例如从枚举两数对的 O(n²)，推到用哈希记录历史值的平均 O(n)。

如果最优方案仍不确定，正确基线可以成为可交付结果和测试参照；先和面试官确认是否希望继续优化。不要为展示套路而浪费大半时间。

2. 双指针移动为什么不是凭感觉？

证明的是整批候选的排除。sum<target 时，对于当前左端 l，所有 j≤r 都满足 a[l]+a[j]≤a[l]+a[r]<target，所以包含 l 的候选都不可能成功。sum>target 时对右端做对称论证。

这里依赖非降序。无序数组没有该关系，直接移动指针可能删掉真正答案；重复值不破坏非降序，因此不影响任意解版本的证明。

3. 面试官不回答某个边界约定怎么办？

明确提出一个合理假设并保持一致，例如“下面按允许无解处理，用 optional 表示失败；如果平台要求固定返回值，我只调整接口”。不要一边假设必有解、一边留下不确定返回路径。

区分题目保证与代码主动校验。有序性如果由题设保证，就不必再花 O(n) 检查；若是在设计通用接口，则应讨论校验责任和代价。

4. 卡住时怎么说，既不沉默也不说无效话？

按“已经确定的事实—具体障碍—下一个实验”表达。例如：“暴力是 O(n²)，瓶颈是重复统计区间和；负数使窗口不单调，我准备改写成两个前缀和之差，检查能否哈希计数。”

约两三分钟没有进展时，可以请求一个方向提示，或与面试官商量先落地基线。收到提示后说明它改变了哪个假设，不要假装此前已经想到。

5. 讲复杂度要包括哪些隐藏成本？

包括排序和建图等预处理、每次操作本身的真实成本、递归栈以及结果输出量。字符串比较不是无条件 O(1)，传值复制 vector 也不是零成本。

分别报告辅助空间和输出空间，并说明哈希平均复杂度或 vector 扩容的均摊复杂度。两指针扫描 O(n) 并不意味着前面带排序的完整算法是 O(n)。

6. 思路、代码和最终结论怎样保持一致？

在编码前给变量写语义，例如 seen 只含严格早于 i 的位置。每段更新都对应这条语义；如果改成先插入再查询，就会在 [3]、目标 6 上重复使用同一位置。

收尾重复契约、核心证明、测试结果和限制。若只完成了基线，明确说基线正确但规模限制下可能超时，不把未验证的优化说成已经交付。

15.02

边界测试与反例设计

知识与适用场景

测试应覆盖结构边界和算法前提。二分测空数组、首尾命中、重复值、全部小于或大于目标；链表测空、单节点、头部删除；DP 测不可达、全负、零容量。

15.2.1 先写预期结果，再运行测试

测试不只是“能否执行到结束”。先依据题意写出预期，再运行并比较。把失败输入缩到尽量短：删除不影响失败的元素、缩小数值、去掉无关边，直到能说明究竟哪条假设错了。所谓最小反例需要说明最小的维度；只做单元素删除得到的是局部不可再删，不一定是全局最小。

确定性回归负责守住已知错误；暴力差分负责在小规模自动找新错误；性质测试负责检查解是否合法；证明负责解释所有合法输入。四者互补，不能互相冒名替代。

15.2.4 差分测试的参照实现必须足够独立

最大子数组的优化实现使用“以当前位置结尾”的状态；参照实现直接枚举左右端点并累加，避免两份代码复制同一个错误递推。随机数组保持短，值域覆盖负数、零和正数；固定 seed，同时在失败时输出完整输入、期望与实际值。

同一 seed 在同一实现环境中便于重现，但 uniform_int_distribution 的映射细节不要求各标准库完全相同，因此跨机器复现优先使用打印出来的数组。先跑手写边界，再随机测试，发现第一处失败就返回非零退出码。

推导 / 不变量

使用已知答案的 assert 进行小规模回归。为了验证最优算法，可以为随机小输入写暴力基线做差分测试：两者不一致时输出原输入，而不是继续运行掩盖错误。

手推一个例子

最大子数组和若全负 [-5,-2,-9]，正确答案是 -2。这个用例能直接发现把 best 初始化为 0 的错误。

C++17
下载 .cpp
long long kadane(const vector<int>& a){
    if(a.empty()) throw invalid_argument("nonempty required");
    long long cur=a[0],ans=a[0];
    for(int i=1;i<(int)a.size();++i){
        cur=max((long long)a[i],cur+a[i]); ans=max(ans,cur);
    }
    return ans;
}
int main(){
    assert(kadane({-5,-2,-9})==-2);
    assert(kadane({0})==0);
    assert(kadane({4,-1,2,1})==6);
    assert(kadane({-2,1,-3,4,-1,2,1,-5,4})==6);
    cout<<"all checks passed\n";
}
复杂度
每个测试调用 O(n)，测试总成本取决于用例规模。差分测试只用于小输入，不把指数暴力放进正式提交。
易错点与边界
assert 在定义 NDEBUG 时会被禁用。随机测试不能替代正确性证明；没有触发 bug 不代表算法一定正确。

15.2.5 可直接运行：最大子数组差分、边界与变形测试

本程序限制数组长度不超过 100000、元素为 int，任意区间和都能放入 long long；空数组主动抛异常。随机部分生成 2000 组长度 1–12 的小数组，O(R·m²) 时间、O(m) 额外空间。反转保留所有连续区间的和值，乘正数 2 保留最优区间的大小关系；乘负数没有该性质。测试不是完整证明，源码需编译运行后才产生测试结果。

long long fastMax(const vector<int>& a) {
    if (a.empty() || a.size() > 100000) throw invalid_argument("size");
    long long ending = a[0], best = a[0];
    for (size_t i = 1; i < a.size(); ++i) {
        ending = max(static_cast<long long>(a[i]), ending + a[i]);
        best = max(best, ending);
    }
    return best;
}
long long slowMax(const vector<int>& a) {
    if (a.empty() || a.size() > 100000) throw invalid_argument("size");
    long long best = LLONG_MIN;
    for (size_t l = 0; l < a.size(); ++l) {
        long long sum = 0;
        for (size_t r = l; r < a.size(); ++r) {
            sum += a[r];
            best = max(best, sum);
        }
    }
    return best;
}
bool checkMax(const vector<int>& a, long long expected) {
    long long actual = fastMax(a);
    if (actual == expected) return true;
    cerr << "input:";
    for (int x : a) cerr << ' ' << x;
    cerr << " expected=" << expected << " actual=" << actual << '\n';
    return false;
}
int main() {
    if (!checkMax({-5,-2,-9}, -2) || !checkMax({0}, 0) ||
        !checkMax({4,-1,2,1}, 6) ||
        !checkMax({INT_MAX,INT_MAX}, 2LL * INT_MAX) ||
        !checkMax({INT_MIN}, INT_MIN)) return 1;
    bool rejected = false;
    try { (void)fastMax({}); } catch (const invalid_argument&) { rejected = true; }
    if (!rejected) { cerr << "empty input accepted\n"; return 1; }
    mt19937 rng(20260922);
    uniform_int_distribution<int> length(1,12), value(-20,20);
    for (int round = 0; round < 2000; ++round) {
        vector<int> a(static_cast<size_t>(length(rng)));
        for (int& x : a) x = value(rng);
        const long long expected = slowMax(a);
        if (!checkMax(a, expected)) return 1;
        reverse(a.begin(), a.end());
        if (!checkMax(a, expected)) return 1;
        for (int& x : a) x *= 2; // small generated values, no int overflow
        if (!checkMax(a, 2 * expected)) return 1;
    }
    cout << "boundary and 2000 differential rounds passed\n";
}

15.2.6 从失败到修复：一条可复现的调试链

错误版本把 best 初始化成 0，输入 [-5,-2,-9] 输出 0。先缩到 [-2] 仍失败，定位到“允许空子数组”的错误语义；修正为首元素初始化，而不是在结尾临时判断全负。把 [-2] 和原输入永久加入回归集，再跑差分。

7. 为何随机测试通过一万次仍不能当正确性证明？

随机输入只覆盖有限样本，罕见边界可能根本没生成，例如全部相等、整数极值、深链、恰好越界的端点。生成器还有自己的分布偏差。

证明必须解释所有合法状态的初始化、保持和终止；随机测试用于寻找反例。若两份实现共享错误初始化，它们可能一致地错，所以还需人工已知答案。

8. 多解问题应该怎样做差分？

两数之和返回任意位置对时，先用暴力判断解是否存在，再检查快算法给出的两个下标不同、范围合法、和值正确。不应强制它返回暴力发现的第一对。

要求全部不同值对时，应把双方按统一顺序规范化再比较，并单独检查重复；优化问题还需比较目标值。路径题则检查起终点、每条边合法及总代价，不能只检查路径长度。

9. assert 与真正的测试失败检查有什么区别？

定义 NDEBUG 后，assert 的表达式不再执行。因此不要把 erase、pop 或其他必要状态更新藏在 assert 中，也不能让正式回归是否生效取决于构建选项。

本章新增测试使用 if 判断并返回非零，或抛 runtime_error 后捕获报告；它们在 Release 模式仍执行。基础示例中的 assert 适合局部演示，但要了解关闭机制。

10. 怎样主动构造能打破贪心或窗口的反例？

先把算法隐含假设写成一句话，再针对它改输入。例如正数窗口假设加入元素不会减小区间和；引入负数 [4,-2,1] 后，超过 3 就删掉 4 会错过总和为 3 的整个区间。

贪心“优先最大面额”可用硬币 [1,3,4]、金额 6：4+1+1 需要 3 枚，而 3+3 只需 2 枚。反例必须满足原题全部条件，否则并没有否定原算法。

11. 编译器警告和 Sanitizer 能查出算法错吗？

警告可以提示可疑转换、未使用变量等；AddressSanitizer 和 UndefinedBehaviorSanitizer 能在实际执行路径上捕捉部分内存错误和未定义行为。它们通常不知道题目预期答案，所以不能代替断言、差分和证明。

本地具备 GCC/Clang 及对应运行库时，可尝试 g++ -std=c++17 -O1 -g -Wall -Wextra -Wconversion -fsanitize=address,undefined detail-differential-tests.cpp -o check；并非所有 Windows 工具链都支持这些选项。先编译成功，再执行程序检查退出码。

12. 失败用例很多时先修哪一个？

先保留第一份可复现输入，明确是答案不符、崩溃还是超时。通常优先修内存越界与未定义行为，因为它们会污染后续观测；再定位契约、状态和逻辑错误。

每次只修一个已解释的原因，重跑原失败和全量回归；不要同时改初始化、边界和更新顺序后只看样例通过，否则无法知道修复依据，也容易引入新错误。

15.3.4 不混用边界：手写 lower_bound 与 upper_bound

前提是数组非降序。lower 的已排除左侧都 <x，右侧都 ≥x；upper 则改为左侧 ≤x、右侧 >x。搜索区间 [l,r) 每次严格缩小。返回值允许等于 size()，代表不存在对应位置，不能直接解引用。equalRange 返回 [first,last)，出现次数为 last-first；时间 O(log(n+1))，额外空间 O(1)。

size_t firstAtLeast(const vector<int>& a, int x) {
    size_t l = 0, r = a.size();
    while (l < r) {
        size_t mid = l + (r - l) / 2;
        if (a[mid] < x) l = mid + 1;
        else r = mid;
    }
    return l;
}
size_t firstGreater(const vector<int>& a, int x) {
    size_t l = 0, r = a.size();
    while (l < r) {
        size_t mid = l + (r - l) / 2;
        if (a[mid] <= x) l = mid + 1;
        else r = mid;
    }
    return l;
}
pair<size_t,size_t> equalRange(const vector<int>& a, int x) {
    return {firstAtLeast(a, x), firstGreater(a, x)};
}

15.3.5 同一份优先级规则：排序和堆的方向恰好相反

定义“更好”为分数更高、同分名字更小、再同名 id 更小；id 约定唯一，使不同记录顺序确定。Better 用于 sort 时把更好的放前面；堆比较器要在 a 比 b 更差时返回 true，故调用 Better(b,a)。返回前 K 个按排名排序的记录，使用完整堆，令 k=min(K,n)，逐次入堆加弹出的比较次数为 O((n+k) log(n+1))。若名字长度上界为 L，每次比较或字符串复制还可能花 O(L+1)，存储字符串的空间上界为 O((n+k)(L+1))。若要 O(n log(k+1)) 次比较，应另设计只保留 K 个的最差元素堆，不能把本示例说成大小 K 堆。

C++17

struct RankedCandidate { string name; int score; int id; };
struct BetterCandidate {
    bool operator()(const RankedCandidate& a, const RankedCandidate& b) const {
        if (a.score != b.score) return a.score > b.score;
        if (a.name != b.name) return a.name < b.name;
        return a.id < b.id;
    }
};
struct LowerPriority {
    bool operator()(const RankedCandidate& a, const RankedCandidate& b) const {
        return BetterCandidate{}(b, a);
    }
};
vector<RankedCandidate> bestCandidates(const vector<RankedCandidate>& a, size_t k) {
    priority_queue<RankedCandidate, vector<RankedCandidate>, LowerPriority> pq;
    for (const auto& item : a) pq.push(item);
    vector<RankedCandidate> result;
    while (!pq.empty() && result.size() < k) {
        result.push_back(pq.top());
        pq.pop();
    }
    return result;
}

13. 严格弱序是否只要求相等时返回 false？

不是。还需要严格关系的传递性，以及“互不小于”所定义的等价关系的传递性等条件。仅检查 comp(x,x)==false 不足以保证合法；剪刀石头布式循环关系就有问题。

多关键字逐层比较可构造字典序。排序过程中不能随意改变外部状态让同一对元素的比较结果变化；测试有限三元组能发现缺陷，但不能取代比较器设计上的证明。

14. sort 与 stable_sort 该怎样选择？

若只按分数比较，又希望同分保持原输入顺序，使用 stable_sort。若需求是同分按名字排序，应在比较器里明确名字键；稳定性并不会自动添加次关键字。

sort 通常是首选，其 C++17 比较次数保证为 O(n log n)。stable_sort 在可用额外内存充足时 O(n log n) 次比较，否则标准允许 O(n log² n)；额外内存策略与实现有关。字符串比较还需乘上实际比较代价。

15. 引用捕获和引用传参分别解决什么问题？

const vector<int>& 参数避免拷贝并表达只读访问，前提是调用期间对象仍存活。lambda 的 [&] 则保存对外部对象的引用，不会延长其生命周期；返回这样的闭包可能留下悬空引用。

值捕获通常持有副本，但捕获一个裸指针只是复制指针，也不等于拥有对象。不要把“用了 const”或“按值捕获”误当作所有生命周期问题的通用保证。

16. vector 和 unordered_map 插入后还能使用旧迭代器吗？

vector 扩容会使所有元素迭代器、指针与引用失效；未扩容的尾插通常保留原元素引用和迭代器，但旧 end 失效。erase 使被删位置及之后的迭代器失效。

unordered_map rehash 使迭代器失效，但不会使未删除元素的引用和指针失效；erase 会使被删元素的引用失效。算法中最稳妥的做法是避免跨可能失效的操作持有迭代器，操作后按键重新 find。

17. 为什么 lower_bound 的 end 不是错误结果？

当全部元素都小于目标时，第一个不小于目标的位置就是尾后位置。空数组同样返回 begin==end。调用方应先判断位置是否小于 size，再检查该位置值是否等于目标。

查某值范围时，用 upper_bound-lower_bound 计算次数，而不是把 upper_bound 指向的元素当成最后一个相等元素。半开区间能自然表示不存在时的空范围。

18. 面试编码哪些简写最容易出问题？

priority_queue::pop 返回 void，取值要先 top 再 pop；auto x 在范围循环中复制，修改原元素要 auto&；memset 不是任意数值填充，初始化一般用容器构造或 fill。

n×m、前缀和、距离加边权都要估计范围，INF 加法先检查可达。getline 接在 operator>> 后可能读到残余换行；确认输入格式后再处理，不能无条件丢弃可能有效的空行。

连续两次独立重写只能说明这道题较熟。真正的掌握还要在不提示题型时识别，解释为什么不选另一算法，并完成至少一道变式；刚看完题解立即复现仅算修复，不算独立完成。

// 小规模暴力基线：用于核对最大子数组和优化实现。
long long bruteMaxSubArray(const vector<int>& a){
    if(a.empty()) throw invalid_argument("nonempty required");
    long long best=LLONG_MIN;
    for(int l=0;l<(int)a.size();++l){
        long long sum=0;
        for(int r=l;r<(int)a.size();++r){
            sum+=a[r]; best=max(best,sum);
        }
    }
    return best;
}
复杂度
暴力基线 O(n²) 时间、O(1) 空间。与本章第 2 节的 O(n) 实现对照，可以用很短随机数组快速定位反例。
易错点与边界
题量不能替代迁移能力。复盘记录：识别信号、暴力瓶颈、不变量/状态、失败用例、修正原因、下次复习日期。

15.4.5 跨章节模拟题：允许负数的目标和子数组计数

题目契约：给定长度不超过 100000 的 int 数组和 long long 目标 k，统计非空连续子数组和等于 k 的个数，不修改输入；空数组返回 0。不要在题目标题里先写“前缀和 + 哈希”，先独立识别。

从枚举 l、r 的 O(n²) 出发，令前缀和 P[0]=0、P[j] 为前 j 个元素之和，则区间 [i,j) 合法当且仅当 P[i]=P[j]-k。扫描 j 时，哈希表保存所有 i<j 的前缀频次；先查询再加入 P[j]，避免在 k=0 时把空区间算进去。多个相同前缀代表多个不同起点，不能用集合代替计数。

用 [1,-1,1]、k=1 手推：初始 freq[0]=1；读第一个 1 查询 0 得 1，答案 1；读 -1 查询 -1 得 0；读最后一个 1 查询 0 得 2，答案 3。再测 []→0、[0,0,0] 且 k=0→6。全零长度 n 的答案 n(n+1)/2，计数类型必须足够大。

15.4.6 综合实现：前缀频次、不变量与数值契约

长度上限使前缀和绝对值至多 100000×2147483648；若 k 超出可实现的子数组和范围可直接返回 0，剩余的 prefix-k 也安全。平均 O(n) 时间、最坏 O(n²) 哈希时间，O(n) 空间。长度校验属于本示例的接口约定，不代表所有同类题都应限制为这个值。

long long countTargetSubarrays(const vector<int>& a, long long k) {
    if (a.size() > 100000) throw invalid_argument("n exceeds contract");
    const long long n = static_cast<long long>(a.size());
    if (k < n * static_cast<long long>(INT_MIN) ||
        k > n * static_cast<long long>(INT_MAX)) return 0;
    unordered_map<long long,long long> frequency;
    frequency[0] = 1;
    long long prefix = 0, result = 0;
    for (int x : a) {
        prefix += x;
        auto it = frequency.find(prefix - k);
        if (it != frequency.end()) result += it->second;
        ++frequency[prefix];
    }
    return result;
}

面试追问：关键点完整解答

19. 题量和速度哪个更能说明掌握？

两者都只是间接指标。优先记录不看提示的成功率、首次方案是否正确、同类错误是否复发、延迟重做能否完成，以及变式迁移情况。为了赶时间跳过测试，可能只是把错误藏到面试里。

10 分钟模板、20 分钟编码等目标只用于自我比较，不能跨难度强行衡量。困难题推进出正确子问题也有价值，复盘要记录真实提示与未完成部分。

20. 看了题解之后怎样避免“我会了”的错觉？

先关掉题解，用自己的话重建契约、不变量和复杂度，再从空文件实现并测边界；这一步仍标记为“借助题解修复”。隔天不看笔记重写，通过后再做一个条件不同的变式。

如果只能记住代码位置而说不出某次移动为什么安全，就回到手推和反例。不要把连续重复同一段代码的短期记忆当成检索和迁移能力。

21. 复习时间不够时哪些题优先？

优先高频基础且反复失败的模式，如二分边界、链表连接、树递归定义、前缀计数和背包方向。已稳定掌握的题延长间隔，陌生高级结构按岗位需求选择，不挤掉基本正确性训练。

把错误分成识别、证明、实现、测试、表达五类，针对最常见的一类安排专项，而不是每次从第一章重新刷一遍。面试前两天以已学内容回归、模拟和休息为主。

22. 自评 18 分就能认为一定通过面试吗？

不能。这里的 20 分表是训练仪表，不是招聘公司的评分制度，分数还受自评宽严影响。应保存录像或代码、失败输入和完成时间，用相同标准观察趋势。

总分也不能掩盖关键缺陷：若输出错误、依赖未声明前提或存在越界，即使表达很好，也应优先修正正确性。可以请同学按同一行为标准复评。

23. 综合计数题为什么不能用普通滑动窗口？

题目允许负数，扩大窗口可能让和变小，收缩也可能让和变大，因此没有正数窗口的单调性。前缀和差等式不依赖元素正负，适用范围更广。

本题求数量而非最长长度，哈希存频次；若改为最长长度，通常存最早出现位置；若改为最短长度，状态选择还要重新推导，不能只换返回变量。

24. 一次模拟结束后，下一步具体做什么？

先用 5 分钟记事实：是否独立、在哪一分钟卡住、哪个输入失败；再挑一个影响最大的原因写修复与回归。下一次训练设一个可观察目标，例如“编码前先声明 [l,r)；结束前主动测试重复值”，而不是“更认真”。

每周汇总前三类重复错误。若同类错误连续出现，减少新题并做两三道同模式的不同变式；目标是让错误不再复发，不是让错题笔记越来越厚。

long long slowCount(const vector<int>& a, long long target) {
    long long result = 0;
    for (size_t l = 0; l < a.size(); ++l) {
        long long sum = 0;
        for (size_t r = l; r < a.size(); ++r) {
            sum += a[r];
            if (sum == target) ++result;
        }
    }
    return result;
}
void checkArray(const vector<int>& a, long long target) {
    vector<pair<int,int>> expected;
    for (size_t i = 0; i < a.size(); ++i)
        for (size_t j = i + 1; j < a.size(); ++j)
            if (static_cast<long long>(a[i]) + a[j] == target)
                expected.emplace_back(min(a[i], a[j]), max(a[i], a[j]));
    sort(expected.begin(), expected.end());
    expected.erase(unique(expected.begin(), expected.end()), expected.end());
    auto found = twoSumOriginal(a, target);
    requireCheck(found.has_value() == !expected.empty(), "two-sum existence");
    if (found) {
        auto [i,j] = *found;
        requireCheck(i < a.size() && j < a.size() && i != j, "indices");
        requireCheck(static_cast<long long>(a[i]) + a[j] == target, "sum");
    }
    requireCheck(uniqueValuePairs(a, target) == expected, "unique pairs");
    requireCheck(countTargetSubarrays(a, target) == slowCount(a, target), "prefix count");
    vector<int> ordered = a;
    sort(ordered.begin(), ordered.end());
    for (int x : {INT_MIN, -5, 0, 5, INT_MAX}) {
        auto [l,r] = equalRange(ordered, x);
        requireCheck(l == static_cast<size_t>(lower_bound(ordered.begin(), ordered.end(), x) - ordered.begin()), "lower");
        requireCheck(r == static_cast<size_t>(upper_bound(ordered.begin(), ordered.end(), x) - ordered.begin()), "upper");
    }
}

章末自测：先遮住答案，完成推导再核对

25. 两数之和哈希先插入后查询，在 [3]、目标 6 上会发生什么？

插入 seen[3]=0 后查询补数 3 会命中自己，错误返回同一位置两次。先查再插入维持表里只有更早位置的不变量；[3,3] 时第二个元素查询会合法命中第一个。

26. 数组 [2,2,2] 中 lower_bound(2) 与 upper_bound(2) 各是什么？

按 0 下标分别是 0 和 3，所以相等范围为 [0,3)，数量 3。upper_bound 是第一个严格大于 2 的位置，不是最后一个 2 的位置；返回 size() 合法但不可解引用。

27. [0,0,0] 中目标为 0 的非空子数组为何是 6 个？

每个连续区间都满足，长度 1、2、3 分别有 3、2、1 个，共 6。前缀频次从 {0:1} 开始，三次查询分别贡献 1、2、3。若先增加当前前缀次数再查，每轮多算一个空区间，得到错误的 9。

28. 为什么测试最大子数组时“给每个元素加 1，答案也加 1”不成立？

一个长度 L 的区间会增加 L，而不同候选长度不同，最优区间也可能改变。例如 [-2,-2] 的答案是 -2，加 1 后 [-1,-1] 的答案为 -1 看似成立，但 [1,1] 的答案 2 变成 4，并不是 3。合法变形必须先证明答案关系。

反转保留连续区间的和值集合；对所有元素乘同一正数 c，所有区间和都乘 c，因此答案也乘 c，前提是数值不溢出且仍保持相同非空约定。

29. greater<int> 为什么使 priority_queue 的堆顶最小？

堆的比较器返回 true 表示第一个参数优先级低于第二个。greater(a,b) 在 a>b 时为真，表示较大的数优先级更低，所以最小元素到堆顶。sort 的比较器语义是“谁排在前面”，不能不加解释地混用两种口述。

30. reserve(10) 后 size() 是 0，写 v[0]=1 为什么不对？

reserve 只预留存储容量，并未创建可按下标访问的元素。operator[] 要求下标小于 size()；容量足够也不能访问不存在的元素。用 push_back(1) 添加，或 resize(10) 后再赋值。

31. 还有五分钟，最优解未完成，怎样交付？

主动说明已完成与未完成部分。如果已有正确基线，展示其输出、测试及复杂度，并明确在最大规模可能超时；如果只是局部实现，指出缺失逻辑和下一步方案。

不要把剩余时间全用于无依据地改代码。优先消除编译和边界错误、解释验证过的结论，并询问面试官希望看优化方向还是现有实现的测试。

32. 学完十五章之后，下一周应该做什么？

先做两次不预告题型的完整模拟，用十项行为表和具体失败用例定位前三个薄弱点。每个薄弱点各选一题基础、一题变式，完成独立实现、口述证明和回归测试。

把成功但依赖提示的题留在复习队列，按相对 D1、D3、D7 重测。若基础已稳定，再按岗位补图论、DP 或高级结构；不必为了“全部学完”而停止复习，也不必从头无差别重刷。
