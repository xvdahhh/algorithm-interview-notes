链表

链表题检验的是对连接关系的控制。先画出要保留的指针，再修改指向；让已处理部分与未处理部分始终有明确入口。

本章怎么学

本章主线：把节点身份、变量指向与连接关系分开

节点是一个存储值和 next 的对象；ListNode* 是保存节点地址的变量。p=q 只改变变量 p 指向哪里，不会移动节点；p->next=q 则真的改变链表中的一条边。同一个节点可以同时被多个指针变量引用，改变其中一个变量不会自动改变其他变量。

本章普通链表算法默认 next 链有限且无环，节点地址在操作过程中保持有效；合并两条链还默认它们不共享节点。判断环、相交和图克隆会单独说明不同前提。先确认前提，再使用模板，避免把无环遍历写到有环输入上。

复杂度中的 n 通常指节点数。原地连接操作不创建新节点，但递归仍占调用栈。深拷贝会创建输出节点，即便辅助空间是 O(1)，把输出计入后总新增内存仍是 O(n)。

03.01

虚拟头结点与有序合并

知识与适用场景

头结点可能改变时，增加 dummy 可以统一处理头部和中间节点。tail 永远指向已构建结果的最后一个节点，每次把较小节点接到尾部。

1.1 节点与地址：为什么值一样不代表是同一个节点？

假设 a、b 是两个不同节点，即使 a->val==b->val，也不能推出 a==b。判断相交、环和深拷贝时，关键都是地址身份。若把值当作节点身份，含重复值的链表会被误判为相交或有环。

ListNode* p=head 只复制地址，开销 O(1)；它不复制后续链。通过 p 改写 p->val 或 p->next，会影响同样指向该节点的其他变量。局部函数参数 head 按值传递时，执行 head=head->next 不会改变调用方的头变量，所以需要返回新头或使用引用参数。

1.2 复杂度取决于是否已经拿到操作位置

已知前驱 pred 时，插入或摘除它的后继只改常数条边，时间 O(1)。但如果题目只给头指针，让你找到第 k 个节点或目标节点前驱，寻找过程仍需 O(k) 或 O(n)。不能只报告最后一次改指针的时间。

单链表无法从当前节点直接取得前驱。特殊题可能通过复制后继值再删除后继来“删除当前值”，但那会改变节点身份与值的对应，且不能用于尾节点；它不是一般意义上删除指定节点对象的通用方法。

安全的插入与摘除：先保存会被覆盖的边

插入时先让新节点连接旧后继，再让前驱连接新节点。若顺序写反，随后 node->next=predecessor->next 就可能变成 node->next=node，制造自环。摘除时保存 removed，先跨过它，再清空 removed->next；两者均为 O(1) 时间和额外空间。

struct ListNode {
    int val;
    ListNode* next;
    explicit ListNode(int value = 0, ListNode* link = nullptr)
        : val(value), next(link) {}
};
void insertAfter(ListNode* predecessor, ListNode* node) {
    if (!predecessor || !node)
        throw invalid_argument("non-null nodes required");
    // 前提：node 是不在当前链中的独立节点。
    node->next = predecessor->next;
    predecessor->next = node;
}
ListNode* detachAfter(ListNode* predecessor) {
    if (!predecessor || !predecessor->next) return nullptr;
    ListNode* removed = predecessor->next;
    predecessor->next = removed->next;
    removed->next = nullptr;
    return removed; // 交给拥有者决定是否销毁
}

1.3 dummy 把“头结点变化”改写成普通前驱操作

dummy 是位于真实头结点之前的辅助节点，dummy.next=head。删除真实头时，只需改 dummy.next；删除中间节点时，改普通前驱的 next。结果入口始终可从 dummy.next 找到。

ListNode dummy(0,head) 是栈上局部对象，函数结束后它会销毁。返回 dummy.next 没问题，因为那是原节点的地址；返回 &dummy 就会产生悬空指针。dummy 的 val 不参与题意，不应靠它的数值判断结束。

删除所有指定值：删除后前驱为何不前进？

不变量：predecessor 之前已经处理完，predecessor->next 是下一个待判断节点。删除后原后继的后继成为新候选，因此前驱不能跳过去；不删除时才将前驱移到候选节点。

例如 [6,6,1,6] 删除 6：dummy 连续摘掉前两个节点，遇到 1 后前驱移到 1，再摘掉尾部 6。时间 O(n)，额外空间 O(1)。若调用方没有独立保存被摘节点的拥有关系，实际工程应采用明确的销毁策略，避免泄漏。

struct ListNode {
    int val;
    ListNode* next;
    explicit ListNode(int value = 0, ListNode* link = nullptr)
        : val(value), next(link) {}
};
ListNode* removeElements(ListNode* head, int target) {
    ListNode dummy(0, head);
    ListNode* predecessor = &dummy;
    while (predecessor->next) {
        ListNode* candidate = predecessor->next;
        if (candidate->val == target) {
            predecessor->next = candidate->next;
            candidate->next = nullptr; // 仅摘除，由节点拥有者管理生命周期
        } else {
            predecessor = candidate;
        }
    }
    return dummy.next;
}

1.4 合并有序链表：tail 的角色与稳定性

下面原模板中的 tail 表示结果的最后一个已选节点；a、b 分别指向两条未处理链的首节点。两条链各自有序，所以两个首节点中较小者也是所有未处理节点中的最小者，可以安全放到结果尾部。

相等时使用 <= 优先选择 a，保持左输入在相等值上的优先级；这使基于此合并的稳定归并排序得以成立。每次只推进被取走的一条链；一侧为空后，另一侧本来有序，直接接上即可。

1.5 链表排序：切断、递归、稳定合并

归并排序不需要随机访问，适合链表。找中点 O(n)，每层合并总 O(n)，递归约 log n 层，总时间 O(n log n)，额外栈 O(log n)，没有新建数据节点。若遗漏 slow->next=nullptr，左递归可能仍收到原链，无法终止。自底向上的分段归并可把辅助空间进一步降为 O(1)，但实现更长。

struct ListNode {
    int val;
    ListNode* next;
    explicit ListNode(int value = 0, ListNode* link = nullptr)
        : val(value), next(link) {}
};
ListNode* mergeSorted(ListNode* a, ListNode* b) {
    ListNode dummy;
    ListNode* tail = &dummy;
    while (a && b) {
        if (a->val <= b->val) {
            tail->next = a;
            a = a->next;
        } else {
            tail->next = b;
            b = b->next;
        }
        tail = tail->next;
    }
    tail->next = a ? a : b;
    return dummy.next;
}
ListNode* sortList(ListNode* head) {
    if (!head || !head->next) return head;
    ListNode* slow = head;
    ListNode* fast = head->next;
    while (fast && fast->next) {
        slow = slow->next;
        fast = fast->next->next;
    }
    ListNode* right = slow->next;
    slow->next = nullptr; // 真正切断，两个递归子问题才会缩小
    ListNode* leftSorted = sortList(head);
    ListNode* rightSorted = sortList(right);
    return mergeSorted(leftSorted, rightSorted);
}

1.6 两数相加：尾部追加与进位状态

例如 [2,4,3] 与 [5,6,4] 表示 342+465=807，输出 [7,0,8]。循环条件必须包含 carry，否则 [9]+[1] 会漏掉最终进位。时间 O(max(m,n))，输出空间 O(max(m,n))，除输出外辅助空间 O(1)。本例按常见题目约定用 [0] 表示零；两个空输入返回空链。

struct ListNode {
    int val;
    ListNode* next;
    explicit ListNode(int value = 0, ListNode* link = nullptr)
        : val(value), next(link) {}
};
ListNode* addTwoNumbers(const ListNode* a, const ListNode* b) {
    // 前提：每个值在 0..9，低位在头部；内存分配成功。
    ListNode dummy;
    ListNode* tail = &dummy;
    int carry = 0;
    while (a || b || carry) {
        int sum = carry;
        if (a) { sum += a->val; a = a->next; }
        if (b) { sum += b->val; b = b->next; }
        carry = sum / 10;
        tail->next = new ListNode(sum % 10);
        tail = tail->next;
    }
    return dummy.next; // 新输出链由调用方拥有并负责释放
}
推导 / 不变量

两个输入链表均有序，因此它们当前头部的较小者也是所有剩余节点中的最小者。接入后只推进被选中的那条链表。

ListNode* mergeTwo(ListNode* a, ListNode* b) {
    ListNode dummy;
    ListNode* tail = &dummy;
    while (a && b) {
        if (a->val <= b->val) { tail->next = a; a = a->next; }
        else { tail->next = b; b = b->next; }
        tail = tail->next;

同一个节点不能被重复接入

原合并模板要求两条输入链不共享节点。若 a==b 指向同一条链头，算法可能先把该节点作为 a 接入，再作为 b 接入，产生自环或其他错误连接。不要把“值相同没关系”误解为“节点地址相同也没关系”。

若题目允许共享尾部，需要在合并逻辑中专门处理 a==b，或先明确输出是否允许共享、是否要求复制；不能直接照搬“两个独立有序链表”的前提。

面试追问：关键点完整解答

合并稳定性由哪个比较符号决定？

选择 a->val<=b->val 时先取左链的相等节点。若输入是原序列的左右两半，这会保留相等元素的原相对次序。改成 < 后数值仍有序，但左右半中的相等节点可能换序。

如果两链表共享尾部，有什么风险？

同一节点可能被当成两个候选重复接入，形成自环或破坏结构。先确认题目是否保证不相交；若允许共享，需要额外处理首次 a==b 的位置，或采用题目要求的复制策略。

为什么删除连续目标值时前驱不前进？

删除后 predecessor 本身没有变，predecessor->next 已经变成新的待检查节点。若再前进，会跳过这个新候选，漏掉连续的重复目标。

dummy 是局部变量，返回 dummy.next 为什么仍有效？

dummy.next 存的是仍然存活的原节点或新建节点的地址，返回它与返回 dummy 自身地址是两回事。示例的普通节点结构没有会递归销毁 next 的析构函数。

已知待删节点，但没有前驱，能 O(1) 删除吗？

一般不能。非尾节点可以在特定题意下复制后继的值再摘除后继，但真正销毁的是后继对象，外部引用能观察到身份与值变化；尾节点没有后继，更无法这样处理。

为什么合并排序比对链表反复找中点的快排更自然？

归并只需顺序访问、切链和线性合并，不依赖随机下标。它的最坏时间 O(n log n) 可直接保证；递归版的 O(log n) 栈也应如实计入空间。

03.02

迭代反转与局部拼接

知识与适用场景

反转时必须保存当前节点的旧后继。prev 表示已反转部分的头，cur 表示未处理部分的头。每轮把 cur 从未处理部分移到已反转部分前端。

2.1 反转的三个入口：prev、cur、next

在整链反转中，prev 指向已反转前缀的头，不是尾；cur 指向尚未处理后缀的头；临时 next 保存 cur 的原后继。每轮把 cur 从未处理部分摘下，放到已反转部分前面。

这三个名字只在当前模板中具有这些含义。合并中的 tail 是尾，局部头插法中的 predecessor 是区间之前的节点，不要把所有模板的 prev 都机械解释成“上一个节点”或“已处理尾部”。

2.2 反转 A→B→C：先保留入口，再改边

窄屏下可左右滑动表格，查看完整内容。

轮次保存 next改 cur->next 后轮末 prev / cur
初始化—未处理 A→B→C；已处理为空null / A
1BA→nullA / B
2CB→A→nullB / C
3nullC→B→A→nullC / null
结束—原头 A 已成为尾，next 为 null返回 C

两种写错顺序的具体后果

若先执行 cur->next=prev 再执行 cur=cur->next，cur 会沿刚改好的反向边前进，原后缀入口丢失。若先 cur=cur->next 再改旧节点的 next，就已经丢失当前待反转节点的操作入口，除非另有变量保存它。

安全顺序固定为：next=cur->next；cur->next=prev；prev=cur；cur=next。证明时同时说明每个原节点恰处理一次、未处理入口不丢失，最终 next 链终止于 nullptr。

2.3 递归反转：返回新头，旧头变成尾

假设 head 后面的子链已经正确反转，原 head->next 现在是反转子链的尾。让它指向 head，再清空 head->next，就把 head 接到新尾部。时间 O(n)，调用栈 O(n)；长链更推荐迭代版。若省略清空，原先 A→B 与新设 B→A 会形成环。

struct ListNode {
    int val;
    ListNode* next;
    explicit ListNode(int value = 0, ListNode* link = nullptr)
        : val(value), next(link) {}
};
ListNode* reverseRecursive(ListNode* head) {
    if (!head || !head->next) return head;
    ListNode* newHead = reverseRecursive(head->next);
    head->next->next = head;
    head->next = nullptr; // 不断开旧正向边会形成二节点环
    return newHead;
}

2.4 局部反转：四个边界要先记住

反转 [left,right]（本节使用从 1 开始的位置）需要保留区间前驱、原区间头、原区间尾和区间后继。反转后前驱连新头，原区间头变成尾并连接区间后继。处理从位置 1 开始的区间时，dummy 充当前驱。

下面使用“区间内部头插法”：原区间头 start 固定作为逐渐后移到尾部的节点，每次把 start 后面的一个节点搬到区间最前。这样外侧链始终有入口，不需要先把整个区间完全摘下来。

局部反转：先验证区间，再执行头插

示例 1→2→3→4→5，反转 [2,4]：before=1、start=2。先把 3 搬到 1 后面，得到 1→3→2→4→5；再把 4 搬到 1 后，得到 1→4→3→2→5。start 一直是节点 2，最后自然连接节点 5。

时间 O(right)，上界 O(n)，额外空间 O(1)。预先探测到 right 是为了在输入越界时不留下已经被部分修改的链；面试若保证范围合法，可以省掉这次验证扫描。

ListNode* reverseBetween(ListNode* head, int left, int right) {
    if (left < 1 || right < left)
        throw invalid_argument("invalid positions");
    ListNode* probe = head;
    for (int i = 0; i < right; ++i) {
        if (!probe) throw out_of_range("position exceeds list length");
        probe = probe->next;
    }
    ListNode dummy(0, head);
    ListNode* before = &dummy;
    for (int i = 1; i < left; ++i) before = before->next;
    ListNode* start = before->next;
    for (int i = 0; i < right - left; ++i) {
        ListNode* moved = start->next;
        start->next = moved->next;
        moved->next = before->next;
        before->next = moved;
    }
    return dummy.next;
}

2.5 K 个一组反转：确认整组存在才动手

groupBefore 指向组前驱，kth 是组末尾，groupAfter 是下组入口。previous 从 groupAfter 开始，保证当前组原头成为新尾时已经接上后续；反转结束后让组前驱连接 kth，再把组前驱推进到 oldHead。

n=5、k=2 得到 2→1→4→3→5，最后一个节点保持原状。每个完整分组先探测 k 步、再反转 k 步，总计 O(n)，不是 O(nk)；额外空间 O(1)。最后不足 k 个时探测到 null 即停止，不先反转再试图补救。

    int val;
    ListNode* next;
    explicit ListNode(int value = 0, ListNode* link = nullptr)
        : val(value), next(link) {}
};
ListNode* reverseKGroup(ListNode* head, int k) {
    if (k <= 0) throw invalid_argument("k must be positive");
    if (k == 1 || !head) return head;
    ListNode dummy(0, head);
    ListNode* groupBefore = &dummy;
    while (true) {
        ListNode* kth = groupBefore;
        for (int i = 0; i < k && kth; ++i) kth = kth->next;
        if (!kth) break;
        ListNode* groupAfter = kth->next;
        ListNode* oldHead = groupBefore->next;
        ListNode* previous = groupAfter;
        ListNode* current = oldHead;
        while (current != groupAfter) {
            ListNode* next = current->next;
            current->next = previous;
            previous = current;
            current = next;
        }
        groupBefore->next = kth;
        groupBefore = oldHead;
    }
    return dummy.next;
}

2.6 回文链表：反转后半段，并在比较后恢复

中点取前半段末尾，奇数长度时中间元素不参与后半段比较。只遍历后半段即可；即使发现不相等，也不能直接 return false 而跳过恢复。时间 O(n)，额外空间 O(1)，正常返回时所有 next 连接恢复。

    if (!head || !head->next) return true;
    ListNode* middle = head;
    ListNode* fast = head;
    while (fast->next && fast->next->next) {
        middle = middle->next;
        fast = fast->next->next;
    }
    ListNode* second = reverseHalf(middle->next);
    middle->next = second;
    ListNode* first = head;
    ListNode* current = second;
    bool equal = true;
    while (current) {
        if (first->val != current->val) equal = false;
        first = first->next;
        current = current->next;
    }
    middle->next = reverseHalf(second);
    return equal;
}

面试追问：关键点完整解答

为什么反转不能先执行 cur=cur->next？

必须在改变入口前保留当前节点和原后继。原模板只有 cur 持有待处理节点，提前推进会失去对该节点的直接控制；先改 next 再沿它走又会走回已反转部分。临时 next 保存旧边，才能把改边和推进解耦。

局部反转之后需要接回哪两条边？

区间前驱连接反转后的新头；原区间头成为尾，连接原区间后继。若采用头插或 previous=groupAfter 的实现，这两条边可能在过程中逐步建立，但仍需按这两个关系检查。

K 个一组反转为什么先探测 k 个节点？

通常题意要求尾部不足 k 个保持原状。先探测确认整组存在，就能在不足时直接退出，避免修改半组后再恢复。

探测一次、反转一次为什么仍是 O(n)？

各完整组彼此不重叠，每组规模 k，被扫描两次总计 2k；所有组加上最后不足一组的探测，总访问量是 O(n)。k 不会独立乘到每个节点外层。

回文链表发现不相等，为什么不立刻返回？

如果函数承诺保留输入结构，必须先完成后半段恢复。可以保存 false 再统一收尾；若提前退出，也要在返回前显式恢复。

递归反转中的 head->next=nullptr 为什么必要？

在反转子链后，原后继被连接回 head；head 仍保留原本指向后继的边，若不清空会形成相互指向。清空使旧头成为真正的尾。

重排能不能靠交换节点的 val 完成？

若题目要求修改节点连接，交换值不符合约定；外部持有节点地址时，也会观察到不同结果。要先确认题目关注值序列还是节点身份和结构。

03.03

快慢指针、环入口与中点

知识与适用场景

快慢指针用于在一次扫描中构造位置差。找中点依赖速度差，找倒数第 k 个依赖固定距离差。检测环时，环内相对速度为一步，必定相遇。

3.1 找中点：快指针终点决定慢指针位置

快指针每轮两步，慢指针每轮一步；两者通常都从 head 出发。对于奇数长度，慢指针能落在唯一中点；对于偶数长度，有左右两个候选，中点模板必须与后续切分需求一致。

while(fast && fast->next) 会在偶数长度返回右中点；先判断空头，再用 while(fast->next && fast->next->next) 会返回左中点。第二种条件在循环开始时保持 fast 非空，但不能省掉初始空头判断。

两种实现时间 O(n)、额外空间 O(1)，默认输入无环。返回值是节点指针，不是下标。用于“先切两半，再反转后半段”时，左中点常便于从 middle->next 取后半段。

3.2 倒数第 k 个：速度相同，但先拉开距离

若 fast 从 head 先走 k 步，再让 slow 从 head 与 fast 同步移动，直到 fast==nullptr，则 slow 正好是倒数第 k 个。两指针之间始终隔 k 条 next 边，终点前还有 k 个节点的位置就是答案。

删除时通常需要的是待删节点的前驱。可以让两个指针都从 dummy 出发，fast 先走 k 步，然后同步走到 fast->next==nullptr。此时 slow->next 就是待删节点。起点和停止条件一起决定偏移，不能混用两套写法。

删除倒数第 k 个：保留前驱以统一头部删除

3.3 Floyd 判环：为什么相遇是必然的？

无环时 fast 先遇到 null 或无法再走两步，循环终止。存在环时，两者最终都进入长度 L 的环；把环内位置看成模 L 的整数，fast 相对 slow 每轮前进 1，所以相对位置最多经过 L 轮就会覆盖到 0，即相遇。

判断的是指针相等 slow==fast。初始时两者都在 head，这不代表有环，必须先推进再比较。空链、单节点无环、单节点自环都要分别想一遍。时间 O(a+L)，其中 a 是入环前长度；额外空间 O(1)。

3.4 找入口：从路程方程推到同步相遇

设头到入口距离为 a，相遇点在环内距入口向前 b 步，环长为 L。相遇时 slow 一共走了 t=a+b+uL 步，u≥0 表示可能绕过的整圈；fast 走了 2t 步。因为同处一个环内位置，路程差 t=mL，其中 m 是正整数。

消去 t，得到 a+b=(m-u)L，也就是 a≡−b（mod L）。这说明从相遇点再走 a 步，恰好落在环入口；与此同时，从 head 走 a 步也恰好到入口。把一个指针放回 head，两者每轮各走一步，首次相遇就是入口。

不需要假设慢指针只走了一段环、不需要计算环长，也不需要把 a 写成恰好一圈减 b。头指针进入环之前，两条路径位于不同区域，不会更早相遇；若 a=0，相遇点本来就在入口，重置后可立即返回。

3.5 快指针改为三步：判环与找入口不是同一结论

若 fast 每轮走 3 步、slow 每轮走 1 步，相遇方程变成 2t 是 L 的倍数。这只能推出 L 整除 2t，不一定推出 L 整除 t，因此不能直接推出 a+b 是 L 的倍数，原找入口过程就失去保证。

具体反例：一个长度 4 的纯环，head 就在入口。两轮后 slow 位于位置 2，fast 走了 6 步也在位置 2，已经相遇。把一个指针重置到位置 0 后，两者同速移动，始终相差 2 个位置，永远不会再相遇。

三倍速从同一头出发仍能在有环时相遇，但找入口需换一种证明支持的方法，例如先测环长 L，再从 head 出发让一指针领先 L 步后同步移动。面试常用一倍/二倍速，是因为判环与入口推导都简洁。

3.6 无环链表相交：走过对方的前缀来消除长度差

把两条链分为独有前缀 A、B 和共同后缀 C。两个指针分别走过 A+C+B 与 B+C+A 后，已经抵消独有前缀的长度差，会在共同后缀入口对齐；经 null 换头的过渡轮对两者是对称的。若不相交，最终会同时到 null。

时间 O(m+n)，额外空间 O(1)。此法比较地址而非数值，不修改 next。若两条链可能有环，不能直接套用；需先分别检测环，再区分无环、有环以及环入口是否相同等情况。

struct ListNode {
    int val; ListNode* next;
    ListNode(int v = 0, ListNode* p = nullptr) : val(v), next(p) {}
};
ListNode* detectCycle(ListNode* head) {
    ListNode *slow = head, *fast = head;
    while (fast && fast->next) {
        slow = slow->next;
        fast = fast->next->next;
        if (slow == fast) {
            ListNode* p = head;
            while (p != slow) { p = p->next; slow = slow->next; }
            return p;
        }
    }
    return nullptr;
}

面试追问：关键点完整解答

fast 每轮走两步，为什么先检查 fast 和 fast->next？

为了读取 fast->next->next，必须确保前两级解引用对象有效。fast->next->next 本身可以是 null，赋给 fast 是合法的；下一轮再由条件阻止解引用。

偶数链表返回哪个中点由什么决定？

由初始位置与停止条件共同决定。本节两个指针同从 head 出发，while(fast&&fast->next) 返回右中点；先排空，再用 while(fast->next&&fast->next->next) 返回左中点。

倒数第 k 个的模板，为什么不能随便换 while 条件？

固定间隔、起点和终点是成套推导的。从 head 起并停在 fast==null，可得到目标；从 dummy 起并停在 fast->next==null，可得到前驱。只改条件可能使结果偏一个节点。

Floyd 相遇后，为什么把一个指针放回头就能找入口？

相遇时 slow 路程 t 是 L 的倍数，同时 t=a+b+uL，因此 a+b 是 L 的倍数。相遇点再走 a 步与 head 走 a 步都到入口，这就是同速移动的依据。

若快指针走三步，找入口步骤还能直接照搬吗？

不能。相遇只保证 2t 是 L 的倍数，不保证 t 是。长度 4 的纯环会在位置 2 相遇，重置一个指针到位置 0 后，两者同速始终间隔 2，无法会合。

两条链表数值序列相同，就相交吗？

不一定。只有共享同一个节点对象才是相交；两份独立分配的 [1,2,3] 不相交。无环单链表一旦共享一个节点，之后 next 路径也相同，因此共享的是整个后缀。

为什么不建议通过修改某条链尾 next 来判断相交？

虽然可以构造环再检测，但会暂时修改输入，需要可靠恢复，也会给共享结构和异常路径带来额外负担。无环输入可直接使用不改连接的双指针或长度对齐，更容易满足常见接口约定。

随机指针复制与深拷贝

知识与适用场景

深拷贝要求新旧节点完全分离，但连接拓扑相同。难点在于 random 可能指向尚未复制的节点，因此将建点和连边分成两个阶段。

4.1 深拷贝规格：值相等，身份不同，边关系对应

深拷贝不是把 head 地址复制一份，也不是仅为每个值新建节点。对于每个原节点 u，必须恰好对应一个新节点 copy(u)，值相同、地址不同；原边 u.next=v 应映射为 copy(u).next=copy(v)，random 也同理，空边仍为空。

若两个原节点的 random 指向同一个目标，两个新 random 也必须指向同一个新目标，不能各自再复制一份。这就是共享结构必须被保留的原因。原链中重复 val 很常见，因此映射的键必须是旧节点地址而非 val。

4.2 两遍哈希复制为什么不依赖 random 的方向？

第一遍只顺着无环 next 链，为所有原节点建立对应的新节点，此时不急于连接 random。第二遍再连接 next 和 random，因为映射已经完整，向前、向后、指向自身或空都能统一处理。

原模板在非空目标处使用 copied.at(...)，表示预期该目标一定已建点。若题目可能让 random 指向 next 链之外，这个预期不成立，需重新定义复制范围，通常改为对 next/random 可达图进行搜索。

哈希方式平均时间 O(n)，辅助映射 O(n)，输出节点 O(n)。它不修改原连接，通常是先写出的可靠解法。示例按分配成功的面试模型讲算法；工程代码若可能分配失败，应使用明确的所有权与清理机制避免半成品泄漏。

4.3 穿插复制：让原节点的 next 临时充当映射

第一步在每个原节点后插入副本，A→A'→B→B'。此时任一旧节点 u 的副本就是 u->next，所以旧目标 u->random 的副本就是 u->random->next。第二步利用这个映射连接所有副本 random。

第三步把原节点与副本节点拆成两条链：恢复 A.next=B，建立 A'.next=B'。拆分只能在 random 全部设置之后进行，否则某些目标的 next 已恢复，不再指向副本，临时映射会被破坏。

三遍穿插复制：连接 random 后再统一拆链

三遍均为 O(n)，除新输出节点外辅助空间 O(1)，正常返回时原链 next 已恢复，原 random 从未修改。第一遍遍历必须跳到保存的 nextOriginal，不能把刚插入的副本当作下一个原节点继续复制。

该实现会暂时改变输入，不能在“不允许修改输入的任何时刻”的约束下使用；也不提供内存分配失败时的回滚保证。若这些条件重要，优先选有独立所有权管理的哈希解法，或额外实现失败恢复。

struct Node {
    int val;
    Node* next = nullptr;
    Node* random = nullptr;

};
Node* copyInterleaved(Node* head) {
    if (!head) return nullptr;
    // 前提：next 无环，random 为空或指向链内；所有 new 均成功。
    for (Node* current = head; current;) {
        Node* nextOriginal = current->next;
        Node* copy = new Node(current->val);
        current->next = copy;
        copy->next = nextOriginal;
        current = nextOriginal;
    }
    for (Node* current = head; current; current = current->next->next) {
        Node* copy = current->next;
        copy->random = current->random ? current->random->next : nullptr;
    }
    Node* copyHead = head->next;
    for (Node* current = head; current;) {
        Node* copy = current->next;
        Node* nextOriginal = copy->next;
        current->next = nextOriginal;
        copy->next = nextOriginal ? nextOriginal->next : nullptr;
        current = nextOriginal;
    }
    return copyHead;
}

4.4 next 也有环时：把复制升级为图克隆

发现节点时立刻建立映射并入队，以后遇到它直接复用副本，不重复展开。这同时处理环、自环和多个节点共享同一目标。时间平均 O(V+E)，每个节点至多两条边，因此此结构中 E≤2V，辅助映射与队列 O(V)，输出 O(V)。

struct Node {
    int val;
    Node* next = nullptr;
    Node* random = nullptr;
    explicit Node(int value) : val(value) {}
};
Node* cloneReachable(Node* root) {
    // 复制从 root 沿 next/random 可达的全部节点；允许环与共享。
    // 每条非空边均需指向有效 Node；按内存分配成功模型处理。
    if (!root) return nullptr;
    unordered_map<Node*, Node*> copies;
    queue<Node*> pending;
    copies[root] = new Node(root->val);
    pending.push(root);
    auto ensureCopy = [&](Node* original) -> Node* {
        if (!original) return nullptr;
        auto it = copies.find(original);
        if (it != copies.end()) return it->second;
        Node* fresh = new Node(original->val);
        copies.emplace(original, fresh);
        pending.push(original);
        return fresh;
    };
    while (!pending.empty()) {
        Node* current = pending.front();
        pending.pop();
        Node* copy = copies.at(current);
        copy->next = ensureCopy(current->next);
        copy->random = ensureCopy(current->random);
    }
    return copies.at(root);
}

4.5 双向链表与 LRU：已知节点时常数时间移动

单链表删除一般需要前驱，双向链表的 prev 能直接提供前驱。把节点从当前位置摘下时，要同时修改前驱的 next 和后继的 prev；插入时也必须维护两个方向。头尾哨兵可统一边界，但哨兵本身不能作为普通数据节点删除。

LRU 用哈希表按 key 找到双向链表节点，命中后将它移到最近使用端，容量满时删最久使用端。哈希提供定位，双向链表提供移动；只用链表则查找是 O(n)。完整缓存设计在第 14 章展开，这里先掌握改边原语。

void unlinkNode(DoubleNode* node) {
    // 前提：node 为已挂接的非哨兵节点，prev/next 均有效。
    DoubleNode* before = node->prev;
    DoubleNode* after = node->next;
    before->next = after;
    after->prev = before;
    node->prev = nullptr;
    node->next = nullptr;
}
void insertAfter(DoubleNode* before, DoubleNode* node) {
    // 前提：before->next 有效；node 是不在链中的独立节点。
    DoubleNode* after = before->next;
    node->prev = before;
    node->next = after;
    before->next = node;
    after->prev = node;
}

深拷贝不能只检查值相同

检查一：新旧节点地址集合没有交集。检查二：每个原节点恰对应一个副本，数量一致。检查三：通过这个映射逐一验证 val、next、random 关系。检查四：修改副本的值不改变原值。若用穿插法，还要确认原 next 已经逐项恢复。

不要通过 random 递归直接 new 而不记忆化，否则共享目标会被复制多份，有环时甚至无限递归。记录“已经为哪个原对象建了副本”是深拷贝正确性的核心。

面试追问：关键点完整解答

浅拷贝和深拷贝在这道题里的区别是什么？

浅拷贝只复制指针或保留指向旧节点的边，新旧结构仍共享对象；深拷贝创建独立节点，并将每条边改为对应新节点之间的边。值相同不是充分条件。

哈希表为什么必须用旧节点指针作键？

节点身份由对象地址区分，重复值不代表同一对象。若用 val 作键，两个值相同的节点会被错误合并，连边与数量都会出错。

穿插法为什么一定要先完成所有 random 再拆分？

random 的副本映射依赖 oldTarget->next 仍指向其副本。提前拆分某一段会恢复这个 next，使后续 random 连接拿到原节点或错误目标。

如果 next 也可能有环，为什么两次普通 for 遍历不成立？

普通 for(p=head;p;p=p->next) 依靠 null 终止，有环就不会结束。需要通过哈希记录已发现节点，并按 next/random 可达边做 BFS 或 DFS，同时复用已有副本。

辅助空间 O(1) 是否代表复制只多用常数内存？

不是。穿插法额外的工作指针为 O(1)，但 n 个新输出节点仍需要 O(n)。报告时应明确“除输出外辅助空间 O(1)”。

LRU 为什么使用哈希表加双向链表？

哈希表平均 O(1) 定位键，双向链表在已知节点时 O(1) 摘除并移到最近使用端。单链表若没有前驱，还要扫描定位前驱；只有哈希则难以维护最久使用顺序。

struct ListNode {
    int val;
    ListNode* next;
    explicit ListNode(int value = 0, ListNode* link = nullptr)
        : val(value), next(link) {}
};

ListNode* reverseKGroup(ListNode* head, int k) {
    if (k <= 0) throw invalid_argument("k must be positive");
    if (k == 1 || !head) return head;
    ListNode dummy(0, head);
    ListNode* groupBefore = &dummy;
    while (true) {
        ListNode* kth = groupBefore;
        for (int i = 0; i < k && kth; ++i) kth = kth->next;
        if (!kth) break;
        ListNode* groupAfter = kth->next;
        ListNode* oldHead = groupBefore->next;
        ListNode* previous = groupAfter;
        ListNode* current = oldHead;
        while (current != groupAfter) {
            ListNode* next = current->next;
            current->next = previous;
            previous = current;
            current = next;
        }
        groupBefore->next = kth;
        groupBefore = oldHead;
    }
    return dummy.next;
}
ListNode* reverseHalf(ListNode* head) {
    ListNode* previous = nullptr;
    while (head) {
        ListNode* next = head->next;
        head->next = previous;
        previous = head;
        head = next;
    }
    return previous;
}

    ListNode* middle = head;
    ListNode* fast = head;
    while (fast->next && fast->next->next) {
        middle = middle->next;
        fast = fast->next->next;
    }
    ListNode* second = reverseHalf(middle->next);
    middle->next = second;
    ListNode* first = head;
    ListNode* current = second;

        if (first->val != current->val) equal = false;
        first = first->next;
        current = current->next;
    }
    middle->next = reverseHalf(second);
    return equal;
}

    require(snapshot(restored) == original, "double reversal failed");

    bool expectedPalindrome = equal(values.begin(), values.begin() + n / 2,
                                    values.rbegin());
    require(isPalindromeRestoring(restored) == expectedPalindrome,
            "palindrome result mismatch");
    require(snapshot(restored) == original, "palindrome did not restore links");
    require(detectCycleForTest(restored) == nullptr, "false cycle detected");
}
int main() {
    try {
        checkCase({}, 2);
        checkCase({7}, 1);
        checkCase({1, 2, 3, 4, 5}, 2);
        checkCase({1, 2, 2, 1}, 3);
        checkCase({1, 2, 3}, 5);

        mt19937 generator(20260920);
        uniform_int_distribution<int> length(0, 14), value(-2, 2), group(1, 7);
        for (int trial = 0; trial < 1000; ++trial) {
            vector<int> values(length(generator));
            for (int& x : values) x = value(generator);
            checkCase(values, group(generator));
        }

        Fixture cyclic({1, 2, 3, 4});
        cyclic.nodes.back().next = &cyclic.nodes[1];
        require(detectCycleForTest(cyclic.head) == &cyclic.nodes[1], "wrong entry");

        Fixture selfLoop({9});
        selfLoop.head->next = selfLoop.head;
        require(detectCycleForTest(selfLoop.head) == selfLoop.head, "self-loop failed");

        Fixture invalid({1, 2});
        auto unchanged = snapshot(invalid.head);
        bool rejected = false;
        try { reverseKGroup(invalid.head, 0); }
        catch (const invalid_argument&) { rejected = true; }
        require(rejected && snapshot(invalid.head) == unchanged, "invalid k changed list");
        cout << "structural checks passed\n";
    } catch (const exception& error) {
        cerr << error.what() << '\n';
        return 1;

章末自测：检查你能否独立解释连接关系

执行 p=q 后，原来 p 指向的节点会自动销毁吗？

不会。普通裸指针赋值只改变地址值，不管理对象生命周期。若那个对象由你动态分配且已经没有其他拥有入口，可能产生泄漏；若它由容器或平台管理，则由对应拥有者负责。

整链反转时 prev 是已处理部分的头还是尾？

在本章迭代反转模板中，它是已反转前缀的头。原来的 head 在第一次改边后就成为最终尾，next 为 null。变量名要服从当前算法的语义。

两次 K 分组反转为何能作为一个测试性质？

固定相同 k 且长度不变时，每个完整分组内部反转两次恢复原顺序，不足一组两次都不变。不过只有这个性质还不够，因为一个完全不做事的错误函数也满足它；因此程序先与数组按组反转的地址参考结果比较，再检查恢复。

回文函数返回 false 时，为什么也要比较恢复后的地址序列？

不相等分支最容易提前返回、跳过恢复。值比较结果正确并不保证输入结构保持原样；应对成功与失败两条路径都验证原 next 链。

两条输入已经是同一条有序链，直接调用普通 mergeTwo 会怎样？

不满足独立输入前提，同一个节点可能反复作为左右候选接入，产生自环。应先澄清共享节点约定，不能因为数值有序就认为模板适用。

Floyd 中 slow、fast 一开始相等，为什么不能立刻判环？

它们是刻意初始化到同一头节点的，不包含任何关于环的信息。必须先按各自速度前进，再比较节点身份；否则任何非空链都会被错误判为有环。

random 自环和 next 自环，对两遍复制的影响一样吗？

不一样。原题遍历只沿 next，random 自环可由已建映射正确连接；next 自环会使普通 next 遍历无法到 null，因此需要带访问记录的图搜索。
