14.01

LRU 缓存：哈希 + 双向链表

知识与适用场景

LRU 淘汰最久未使用的键。哈希提供按键 O(1) 定位，双向链表提供 O(1) 移动和删除。约定链表头为最近使用，尾为最久未使用。

1.1 LRU 的不变量不只是“有一个哈希表和一个链表”

链表从前到后按最近使用到最久未使用排序，表中每个 key 恰好指向链表里同 key 的唯一节点，两个结构键集合相同，节点数不超过容量。get 命中改变新旧顺序，未命中不改变；put 已有键修改值并刷新顺序，而不是增加一个重复节点。

splice 移动同一 list 中的节点不会让该节点迭代器失效，所以无需重新建立映射。删除则会使该节点迭代器失效，必须同步删映射。list 不能 O(1) 按 key 定位，哈希不能直接得到最久未使用者，两者缺一不可。

1.3 LFU 的平局规则决定第二层结构

LFU 优先淘汰使用频率最小的键，同频率时再淘汰最久未使用者。因此维护 key→节点信息、frequency→按最近程度排列的键链表，以及 minFrequency。访问一个键要从旧频率桶移除，插入频率+1 桶的头部。

本章约定新键频率为 1，get 命中和 put 更新现有键都算一次访问。若最小频率桶因提升一个键而变空，最小频率可升为旧值+1，因为刚移动的键保证新桶存在。这个结论依赖没有任意 erase 或缩容；增加那些接口时不能照抄 minFrequency++。

class LRUCache {
    size_t cap;
    list<pair<int,int>> order;
    unordered_map<int,list<pair<int,int>>::iterator> pos;
public:
    explicit LRUCache(int capacity):cap(max(0,capacity)){}
    LRUCache(const LRUCache&)=delete;
    LRUCache& operator=(const LRUCache&)=delete;
    int get(int key){
        auto it=pos.find(key);
        if(it==pos.end()) return -1;
        order.splice(order.begin(),order,it->second);
        return it->second->second;
    }
    void put(int key,int value){
        auto it=pos.find(key);
        if(it!=pos.end()){
            it->second->second=value;
            order.splice(order.begin(),order,it->second);
            return;
        }
        if(cap==0) return;
        order.emplace_front(key,value);
        pos[key]=order.begin();
        if(order.size()>cap){
            pos.erase(order.back().first);
            order.pop_back();
        }
    }
};

class OptionalLRU {
    size_t capacity;
    list<pair<int,int>> order;
    unordered_map<int,list<pair<int,int>>::iterator> position;
    void trim() {
        while (order.size() > capacity) {
            position.erase(order.back().first); order.pop_back();
        }
    }
public:
    explicit OptionalLRU(int cap) {
        if (cap < 0) throw invalid_argument("capacity");
        capacity = (size_t)cap;
    }
    OptionalLRU(const OptionalLRU&) = delete;
    OptionalLRU& operator=(const OptionalLRU&) = delete;
    optional<int> get(int key) {
        auto it = position.find(key);
        if (it == position.end()) return nullopt;
        order.splice(order.begin(),order,it->second);
        return it->second->second;
    }
    void put(int key, int value) {
        auto it = position.find(key);
        if (it != position.end()) {
            it->second->second = value;
            order.splice(order.begin(),order,it->second); return;
        }
        if (!capacity) return;
        order.emplace_front(key,value); position[key] = order.begin(); trim();
    }
    bool erase(int key) {
        auto it = position.find(key);
        if (it == position.end()) return false;
        order.erase(it->second); position.erase(it); return true;
    }
    void resize(int cap) {
        if (cap < 0) throw invalid_argument("capacity");
        capacity = (size_t)cap; trim();
    }
    size_t size() const { return order.size(); }
};

1.6 LFU：频率桶里的 LRU 平局淘汰

每次操作只移动一个节点、查询少量哈希项，平均 O(1)，空间 O(capacity)。空桶及时删除，桶数不会随历史访问次数无限增长。频率使用 uint64_t，并在增长溢出前抛错。本教学版无 erase/resize；不支持并发操作，也不提供内存分配失败时的强异常保证。

class LFUCacheExample {
    struct Entry { int value; uint64_t frequency; list<int>::iterator where; };
    size_t capacity;
    uint64_t minimum = 0;
    unordered_map<int,Entry> entries;
    unordered_map<uint64_t,list<int>> buckets;
    void touch(int key) {
        auto& entry = entries.at(key);
        uint64_t old = entry.frequency;
        if (old == UINT64_MAX) throw overflow_error("frequency");
        auto bucket = buckets.find(old);
        bucket->second.erase(entry.where);
        if (bucket->second.empty()) {
            buckets.erase(bucket);
            if (minimum == old) minimum = old+1;
        }
        entry.frequency = old+1;
        auto& target = buckets[old+1];
        target.push_front(key); entry.where = target.begin();
    }
public:
    explicit LFUCacheExample(int cap) {
        if (cap < 0) throw invalid_argument("capacity");
        capacity = (size_t)cap;
    }
    LFUCacheExample(const LFUCacheExample&) = delete;
    LFUCacheExample& operator=(const LFUCacheExample&) = delete;
    optional<int> get(int key) {
        auto it = entries.find(key);
        if (it == entries.end()) return nullopt;
        int result = it->second.value; touch(key); return result;
    }
    void put(int key, int value) {
        auto it = entries.find(key);
        if (it != entries.end()) {
            touch(key); entries.at(key).value = value; return;
        }
        if (!capacity) return;
        if (entries.size() == capacity) {
            auto bucket = buckets.find(minimum);
            int victim = bucket->second.back();
            bucket->second.pop_back(); entries.erase(victim);
            if (bucket->second.empty()) buckets.erase(bucket);
        }
        auto& bucket = buckets[1]; bucket.push_front(key);
        entries.emplace(key,Entry{value,1,bucket.begin()}); minimum = 1;
    }
    size_t size() const { return entries.size(); }
};

1.7 高频 Top K：固定平局规则，让堆顶始终最差

返回频率降序、同频数值升序的 K 个不同值。priority_queue 的比较器表示 x 比 y 更靠后；把“更好”关系放进去，堆顶就是最差候选，超容量淘汰它。U 为不同值数，时间平均 O(n+U log(K+1)+K log(K+1))，空间 O(U+K)，并非 O(K) 总内存。

vector<int> topKFrequentStable(const vector<int>& a, int k) {
    if (k < 0) throw invalid_argument("k");
    unordered_map<int,long long> count;
    for (int x : a) ++count[x];
    if ((size_t)k > count.size()) throw invalid_argument("k exceeds distinct count");
    if (!k) return {};
    using Candidate = pair<long long,int>; // 频次、数值
    auto better = [](const Candidate& x, const Candidate& y) {
        if (x.first != y.first) return x.first > y.first;
        return x.second < y.second;
    };
    priority_queue<Candidate,vector<Candidate>,decltype(better)> heap(better);
    for (auto [value,frequency] : count) {
        heap.push({frequency,value});
        if ((int)heap.size() > k) heap.pop();
    }
    vector<Candidate> kept;
    while (!heap.empty()) { kept.push_back(heap.top()); heap.pop(); }
    sort(kept.begin(),kept.end(),better);
    vector<int> answer;
    for (auto [frequency,value] : kept) answer.push_back(value);
    return answer;
}

面试追问：关键点完整解答

get 为什么也要改链表？

LRU 的最近使用包括读取命中。若只在写入时刷新，得到的是接近写入顺序的策略，不再是题目定义的 LRU。get 未命中则不产生节点，也不改变现有键顺序。

链表换成 vector 会怎样？

vector 随机访问快，但将中间节点移到最前面通常要移动 O(n) 元素，保存的下标也要随之修正。双向链表支持已知节点 O(1) 摘除与插入；哈希负责让“已知节点”这一步也平均 O(1)。

为什么缓存对象禁用默认拷贝？

链表会被复制成新节点，但默认复制的哈希值仍是旧链表的迭代器。副本操作可能访问或移动原对象节点，破坏所有权。要么禁用拷贝，要么自定义拷贝后重新建立指向新链表的映射。

LFU 为什么还需要每个频率桶里的顺序？

只知道频率无法解决同频淘汰。例如两个键都访问过两次，要根据哪个更久没用来选择。每个桶维护最近到最旧顺序，淘汰最小频率桶的尾部，两个优先级才完整。

LFU 最小频率何时能直接加一？

当一次 touch 把某键从最小频率 f 桶移到 f+1，且 f 桶恰好变空时，刚移动的键保证 f+1 桶非空，因此 minimum=f+1 合法。任意删除最小桶最后一项时没有这个保证，可能需要跳到更远的频率。

精确在线高频 Top K 能否只保存 K 个计数？

一般不能。当前不在前 K 的值可能在未来大量出现，如果此前频率已丢失，就无法精确比较。普通方案要为所有不同值保留计数；Misra-Gries 等节省内存的方法是有条件的候选或近似方案，常需第二遍验证，不等价于精确全流排名。

快选得到前 K 项后，为何还可能要排序？

快选仅保证分区与秩条件，候选内部并不有序。若接口只要集合，可以不排序；若要求按大小、频次或特定平局规则输出，还需对选中的 K 项排序，计入 O(K log K)。

14.02

扫描线：并发数量与端点规则

知识与适用场景

把区间开始转成 +1 事件，结束转成 -1 事件，排序后维护活跃数量。重点不在求和，而在同一时间发生的事件谁先处理。

2.1 扫描的对象是相邻事件坐标之间的一整段

对半开区间 [l,r)，在 l 加一、在 r 减一。同坐标所有事件合并处理后，active 表示从当前坐标 t 到下一不同坐标 next 的整段并发量，不是只在 t 这个孤立点成立。记录峰值时间段时，应把这个状态与 [t,next) 关联。

基础模板逐事件按 (time,delta) 排序，相同时间先结束再开始，适合求半开区间最大值。补充版本按坐标分组，用净变化更新，避免把同一时刻的中间处理状态误当作真实时间段。没有下一坐标时无需记录一段无穷区间。

2.4 最小会议室数等于最大同时占用量

任何时刻同时开会的 k 场必须占 k 个不同房间，因此峰值并发是房间数下界。按开始时间处理，把所有 end≤start 的房间释放；有空房就复用，没空房才开新房。每次开新房时，现有房间都被正在进行的会议占用，说明确实达到新的并发下界。

这给出了达到下界的分配方案，故算法最优。若只要数量可用扫描线；需要具体房间编号时，用结束时间堆和空闲编号堆，结果会更直接。只弹一个空闲房间的某些计数实现也能成立，但其堆语义不同，不能拿它声称保存所有当前活跃会议。

推导 / 不变量

会议采用 [start,end) 时，某会议结束的瞬间可以开始下一场，故相同时间先处理 -1，再处理 +1。闭区间且端点重叠时需要反过来。

为什么同时间先 +1 再 −1 可能把会议室数算大？

半开区间的旧会议在终点已经结束，新会议在该点才开始，可以使用同一个房间。先加后减会产生并不存在的瞬时同时占用，例 [0,1)、[1,2) 本应只需 1 间。

每条行程的人数不同。两条各 10 人的行程与两条各 1 人的行程区间数相同，但容量需求完全不同。事件增量应是人数，累加用足够宽的整数。

离散化后能否用排名差当实际持续时间？

不能，排名只保留顺序。事件时间 1、100、101 变成 0、1、2 后，两段排名长度都为 1，真实长度却是 99 与 1。若计算忙碌时长或时间积分，必须用原坐标差，并先转宽整数再相减。

知识与适用场景

3.1 随机集合的两个 O(1) 能力来自不同结构

3.4 Fisher–Yates 与蓄水池的证明切入点

洗牌从后往前固定一个位置：剩 n 个候选时，每个以 1/n 概率放到最后；再在剩下 n−1 个里均匀决定下一位置。因此任意排列概率为 1/n!。关键是缩小选择范围，不是在每一步都从整个数组挑下标。

蓄水池先保留前 K 项。处理第 t 项时均匀取 j∈[0,t−1]，若 j<K 就替换第 j 个样本。新项入样概率 K/t；旧项此前在样本中的概率 K/(t−1)，本轮存活概率 1−1/t，相乘仍为 K/t。完整子集均匀性还可归纳得到每个 K 子集概率 1/C(t,K)，不能仅凭相同边际概率就断言任意算法都对子集均匀。

    unordered_map<int,unordered_set<size_t>> positions;
    mt19937 rng;
public:
    explicit RandomizedMultisetExample(uint32_t seed = 5489U): rng(seed) {}
    bool insert(int x) {
        auto& places = positions[x];
        bool newValue = places.empty();
        places.insert(data.size()); data.push_back(x); return newValue;
    }
    bool eraseOne(int x) {
        auto it = positions.find(x);
        if (it == positions.end()) return false;
        size_t index = *it->second.begin(), lastIndex = data.size()-1;
        int lastValue = data.back();
        it->second.erase(index);
        if (index != lastIndex) {
            data[index] = lastValue;
            auto& lastPlaces = positions.at(lastValue);
            lastPlaces.erase(lastIndex); lastPlaces.insert(index);
        }
        data.pop_back();
        if (it->second.empty()) positions.erase(it);
        return true;
    }
    optional<int> getRandom() {
        if (data.empty()) return nullopt;
        uniform_int_distribution<size_t> choose(0,data.size()-1);
        return data[choose(rng)];
    }
    size_t count(int x) const {
        auto it = positions.find(x);
        return it == positions.end() ? 0 : it->second.size();
    }
    size_t size() const { return data.size(); }
};

class ReservoirSample {
    size_t capacity;
    uint64_t seen = 0;
    vector<int> samples;
    mt19937 rng;
public:
    ReservoirSample(int k, uint32_t seed = 5489U): rng(seed) {
        if (k < 0) throw invalid_argument("k");
        capacity = (size_t)k;
    }
    void offer(int value) {
        if (seen == UINT64_MAX) throw overflow_error("stream length");
        ++seen;
        if (samples.size() < capacity) samples.push_back(value);
        else if (capacity > 0) {
            uniform_int_distribution<uint64_t> choose(0,seen-1);
            uint64_t index = choose(rng);
            if (index < capacity) samples[(size_t)index] = value;
        }
    }
    vector<int> snapshot() const { return samples; }
    uint64_t processed() const { return seen; }
};

void fisherYatesShuffle(vector<int>& values, mt19937& rng) {
    for (size_t remaining = values.size(); remaining > 1; --remaining) {
        uniform_int_distribution<size_t> choose(0,remaining-1);
        size_t picked = choose(rng);
        swap(values[remaining-1],values[picked]);
    }
}

面试追问：关键点完整解答

删除时，若待删位置就是数组末尾还需要交换吗？

不需要填洞，但仍要从对应下标集合或映射删除该位置，再 pop_back。如果统一写交换，也要保证不会在删掉映射后再次误用它。补充实现用 index!=lastIndex 分支明确跳过多余搬移。

重复值映射到单一下标为什么不够？

同一个值可能存在多份。只记一个位置会丢失其他实例的位置，删除后无法定位剩余副本。下标集合能在平均 O(1) 取出一个位置，并在末尾填洞时同步更新。

为什么不建议使用 rand()%n？

如果随机源取值范围大小不是 n 的倍数，某些余数会比另一些多一次映射，产生偏差。uniform_int_distribution 按目标范围生成均匀整数，通常通过拒绝采样等方式避免这种取模偏差。

每次都从全数组随机换一个位置，为什么不是均匀洗牌？

以 n=3 为例，这种算法有 3³=27 条等概率选择路径，但共有 6 个排列，27 不能被 6 整除，因此不可能每个排列次数相等。Fisher–Yates 的路径数为 3·2·1，恰与排列数对应。

蓄水池为什么挑 [0,t−1]，而不是只挑 [0,K−1]？

只挑样本槽会让每个新项必定进入，并过度偏向最近数据。扩大到 t 个位置后，仅前 K 个下标触发替换，新项入样概率降为 K/t，才能与所有历史位置平衡。

固定种子是否意味着随机算法失去意义？

固定种子使同一实现的实验可复现，不改变算法应如何分配抽样范围；但生成的是确定性伪随机序列，不适合作为不可预测的安全机制。测试不应因为短样本频率不完全相等就判错，也不能因频率看起来接近就当作均匀性证明。

蓄水池能否直接维护最近一小时的均匀样本？

不能直接套。普通蓄水池从所有已处理位置抽样，不会自动剔除过期位置。时间窗口的样本需要额外的过期处理与重新加权设计，不能只删除样本中过期项后继续用总历史 seen 作为分母。

知识与适用场景

4.1 欧几里得算法与最小负数

若 a=qb+r，则同时整除 a、b 的数也整除 b、r，反之亦然，因此两对数的公因子集合相同，gcd(a,b)=gcd(b,r)。持续取余直到余数为 0，剩下的非零数就是最大公约数；本章约定 gcd(0,0)=0。

对有符号整数先取幅值时要小心：LLONG_MIN 的绝对值是 2^63，无法放入 long long。abs(LLONG_MIN) 或直接 -LLONG_MIN 都可能溢出。补充接口把幅值保存在 uint64_t 中，负数先安全计算 −(x+1)，再加 1。

4.6 不依赖 __int128 的模乘、模幂与小模数逆元

模乘通过二进制拆分和安全加法避免 a*b 溢出，支持整个 uint64_t 模数范围。两数均小于 mod 时，若 a≥mod−b 就算 a−(mod−b)，否则 a+b 一定小于 mod 且不溢出。模乘 O(log(mod+1))，模幂 O(log(exponent+1)·log(mod+1))，不是把乘法当常数后的普通快速幂界。

uint64_t multiplyMod(uint64_t a, uint64_t b, uint64_t mod) {
    if (mod == 0) throw invalid_argument("mod");
    a %= mod; b %= mod;
    uint64_t answer = 0;
    while (b) {
        if (b&1U) answer = addReducedMod(answer,a,mod);
        b >>= 1;
        a = addReducedMod(a,a,mod);

}
uint64_t powerMod(uint64_t base, uint64_t exponent, uint64_t mod) {
    if (mod == 0) throw invalid_argument("mod");
    uint64_t answer = 1%mod;
    base %= mod;
    while (exponent) {
        if (exponent&1U) answer = multiplyMod(answer,base,mod);
        exponent >>= 1;
        base = multiplyMod(base,base,mod);
    }
    return answer;
}
optional<long long> inverseModSmall(long long a, long long mod) {
    if (mod < 2 || mod > 1000000000) throw invalid_argument("2 <= mod <= 1e9");
    a %= mod; if (a < 0) a += mod;
    long long oldR = mod, r = a, oldT = 0, t = 1;
    while (r) {
        long long q = oldR/r;
        long long nextR = oldR-q*r, nextT = oldT-q*t;
        oldR = r; r = nextR; oldT = t; t = nextT;
    }
    if (oldR != 1) return nullopt;
    oldT %= mod; if (oldT < 0) oldT += mod;
    return oldT;
}

class SmallestPrimeTable {
    int limit;
    vector<int> spf, primeList;
public:
    explicit SmallestPrimeTable(int n): limit(n) {
        if (n < 0 || n > 1000000) throw invalid_argument("sieve limit");
        spf.assign(n+1,0);
        for (int i = 2; i <= n; ++i) {
            if (spf[i] == 0) { spf[i] = i; primeList.push_back(i); }
            for (int p : primeList) {
                if (p > spf[i] || 1LL*p*i > n) break;
                spf[p*i] = p;
            }
        }
    }
    const vector<int>& primes() const { return primeList; }
    bool isPrime(int x) const {
        if (x < 0 || x > limit) throw out_of_range("x");
        return x >= 2 && spf[x] == x;
    }
    vector<pair<int,int>> factorize(int x) const {
        if (x < 1 || x > limit) throw out_of_range("1 <= x <= limit");
        vector<pair<int,int>> factors;
        while (x > 1) {
            int p = spf[x], exponent = 0;
            while (x%p == 0) { x /= p; ++exponent; }
            factors.push_back({p,exponent});
        }
        return factors;
    }
};

面试追问：关键点完整解答

先除后乘是否保证 LCM 不溢出？

不保证，只减少不必要的中间放大。互质的大数 a、b 的 LCM 仍是 a*b，可能超过输出类型。乘法前检查 reduced>MAX/b，满足时返回失败；事后看乘积是否变小已无法避免有符号溢出的未定义行为。

为什么 abs(LLONG_MIN) 是陷阱？

有符号范围负侧比正侧多一个值，最小负数的绝对值无法放回同一有符号类型。先对 x+1 取负再转无符号并加一，能得到 2^63 而不执行溢出的有符号取负。

模意义下能不能直接约掉同一因子？

只有该因子与模数互质、具有逆元时才能作为可逆乘法约去。例如 2x≡2 mod 6 有 x≡1 或 4 两种剩余类，直接除以 2 写成 x≡1 mod 6 会丢解。解同余方程与普通整数除法不同。

费马小定理求逆元有什么前提？

模数 p 必须为质数，且 a mod p 非零，才有 a^(p−1)≡1，从而逆元为 a^(p−2)。对一般模数只要 gcd(a,m)=1 也可逆，但应使用扩展欧几里得等适用方法，不能擅自用 m−2 指数。

无符号溢出定义为回绕，为什么仍不能直接模乘？

回绕相当于先对 2^64 取模，再对 m 取模，通常不等于对原精确乘积直接模 m。行为有定义不代表结果符合数学目标。安全模乘避免丢失那些高位信息。

为什么埃氏筛从 p² 而不是 2p 开始？

2p、3p 等小于 p² 的倍数都含有小于 p 的质因子，已在更早的轮次被标记。从 p² 开始跳过重复工作，不会遗漏合数。判断 p²≤n 时可用 p≤n/p，实际标记起点先在宽类型计算。

筛法、试除和最小质因子表如何选择？

只判少数不大的整数可试除；需要区间内全部质数用筛法；同一上界内大量分解用最小质因子表。上界过大时内存会成为瓶颈，可能需要分段筛或更专门的数论算法，不能只看单次查询很快。

平均 O(1) 的设计题为什么仍可能偶尔慢？

哈希碰撞与 rehash、vector 扩容、内存分配都可能使某次操作较慢。算法面试通常要求平均或均摊界，并非硬实时延迟。应准确说明复杂度类型，而不是把所有操作宣称为每次最坏常数。

怎样检查多个结构保存的同一份数据没有失配？

定义可遍历的不变量：缓存键集合一致且迭代器指向同 key；随机集合中每个位置在对应值的下标集合里且没有幽灵下标；分配方案中每条非空会议恰好有一个房号。测试中用小规模朴素模型逐操作比较，比仅看最后输出更容易定位错误。

数据流、在线与离线各意味着什么？

数据流强调逐项到达及可能受限的保存空间；在线要求当前答案不依赖未来输入；离线允许先拿到全部数据并排序或重排处理。大小 K 堆可以在线维护数值 Top K，但精确频率 Top K 的计数仍可能随不同值数增长；不能把“用了堆”直接等同于固定内存。

    vector<int> points;
    for (auto [l,r] : intervals) if (l < r) { points.push_back(l); points.push_back(r); }

        }
    }
    return result;
}
